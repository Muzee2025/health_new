## 候选模型与依据

以下为2026-11-01访问的开发者原始模型卡，正式部署需固定模型修订、量化文件、许可证和运行时版本并实测。

| 模型 | 真实类型 | 本项目拟分工 | 原始依据 |
| --- | --- | --- | --- |
| Qwen3-8B，候选GGUF Q4_K_M | 通用语言模型的4bit量化版本 | 多角色文本分析、证据整理与摘要草稿 | [官方GGUF模型卡](https://huggingface.co/Qwen/Qwen3-8B-GGUF) |
| Qwen3-Embedding-0.6B | 文本向量模型，0.6B | 在授权范围内召回记录与资料；时间归并由代码实现 | [官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) |
| Qwen3-Reranker-0.6B | 文本重排模型，0.6B | 重排候选片段；相关性不是心理风险分 | [官方模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) |

[官方本地推理说明](https://qwen.readthedocs.io/en/latest/run_locally/llama.cpp.html)及[llama.cpp构建说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)支持讨论Windows/CUDA本地路线；这不是本机或用户服务器已运行的证据。

容量仅作为规划判断：GPU1优先放量化8B语言模型，GPU2放小型Embedding/Reranker。每卡分别安排权重、KV缓存、运行时和批量余量，不能把两卡看作一块自动共享的24GB显存。先用短上下文和低并发测量，再确定上下文、调度与并发上限。没有本轮显存、延迟、吞吐或模型效果结果，不作容量承诺。量化文件体积也不能直接当作推理峰值显存。

本地部署卖点拟表述：“依托已有双GPU设备，拟将授权文本推理和资料检索部署在校内，减少对外部模型接口的依赖，并由校方控制访问和更新。”只有出站路径、日志、存储、权限及模型调用均验证后，才能声称特定数据处理不出校；不将本地部署等同于自动满足隐私或安全要求。

相比旧候选清单，首版建议把云端Qwen3.6-Plus替换为量化开源Qwen3-8B，把检索能力调整为本地Embedding＋Reranker。Emohaa保留为研究参考，音视频、语音生成和配图不占本图的核心分析链路；未替用户修改其他旧稿或宣布这些扩展永久取消。
