# 求助与跟进页面接入

> owner: B / Lead验收 ｜ version: 0.4 ｜ status: 前端与隔离SQLite技术验收通过 ｜ updated: 2026-10-22

本文记录 SUP-FE 对现有页面的业务接入，不表示学校已承诺响应时效、服务流程已正式运行或系统整体上线。

## 范围与契约

- 学生的 `/student/questions` 保留现有路由，升级为“向老师留言”表单与本人历史。使用 `GET /api/student/questions`、`POST /api/student/questions`；历史展示服务端答复、等待状态及 `response_state=unassigned` 的明确分配说明。
- 学生可从预约页和智能助手进入留言；页面说明留言由分配教师查看，不承诺答复时效，也不提供紧急响应。
- 教师新增懒加载二级路由 `/teacher/support`。工作台和“我的学生”提供次入口，一级菜单仍为工作台、我的学生、预约管理、干预记录、内容与档案。
- 工作区用 `/api/teacher/questions?status=...` 与 `/api/teacher/questions/{id}/answer` 处理明确分配学生的留言；`/api/teacher/follow-ups` 及其 complete/cancel 动作管理内部任务；`/api/advanced-teacher/warnings` 与 `/api/teacher/crisis/{warning_id}/reviews` 展示当前分配范围内预警及持久审核历史。
- 预警审核使用 `POST /api/teacher/crisis/review` 并要求填写原因。单生档案的 Word 导出改用 `GET /api/advanced-teacher/students/{student_id}/export/docx`；教师聚合大屏导出继续留在原接口。
- 跟进创建将 `datetime-local` 的选定时间编码为带时区的 ISO UTC（`Z`）；响应日期按浏览器本地时间展示。内部跟进摘要、结果和取消原因不进入学生端。
- 教师预约“通过”动作使用后端 `confirmed`，筛选按规范化后的 `confirmed` 匹配；旧 `approved` 仅兼容显示为“已确认”。学生端分别显示“已确认”和“已完成”。

## 交互与数据边界

- 学生可见答复和教师内部跟进摘要／结果使用不同标签与接口。跟进任务不作为学生消息展示。
- 处理后的预警由审核历史接口回读；已存在但没有 review 事件的记录显示“没有可追溯的审核原因”，不补造结论。
- 未启用 schema 的脱敏 503显示“求助与跟进服务尚未启用，请联系管理员”；401、403、404、409、422只显示中文状态说明，不展示后端详情或请求 URL。
- 表单阻止重复提交，加载显示状态；留言页离开会取消未完成读取并忽略迟到的提交结果。工作区离开会中止在途请求，并通过请求序号防止筛选切换的旧响应覆盖新结果。
- 工作区按学生留言、预警、跟进三个区域分别保留错误和schema状态；一个区域的成功刷新不会清除另一区域的失败。预警审核历史逐条读取，加载中、未读取、读取失败和读取成功但无历史分别显示；失败项可单独重试，不将网络错误解释为“没有可追溯原因”。
- 页面无合成业务记录；空态复用 `LibraryEmpty`，图标／静态视觉继续从已登记素材库读取。

## 导航说明

学生保留六个一级分组： 首页、自助成长（心理测评／心理科普）、预约咨询、智能助手、匿名树洞、我的（报告）。学生留言从预约和助手的次入口进入，不新增一级菜单。

教师保持五个一级分组。求助与跟进是二级工作区，从工作台或我的学生页进入；教师档案个体导出只在学生详情中进行。

## 验收记录

目标浏览器流程为：学生提交留言 → 学生查看等待／未分配状态 → 教师对分配范围内留言答复 → 学生刷新看到答复；教师另完成预警审核、读取原因历史，并创建、完成或取消一项跟进任务；学生详情导出只调用所选学生的单生 endpoint。
