## 0. 结论摘要

**结论一（依赖）**：`python-docx` **不是**残留，是教师端 DOCX 导出的硬运行时依赖，从 core 依赖删除会让应用启动失败；`pymysql` **是**残留，仓库里只有旧建库脚本和环境变量模板引用它，`backend/app/` 内 0 处 import。

**结论二（六组接口）**：六组里只有 **1 组是字面重复**（`/articles/page`，两侧都只调同一个 `page_articles` 服务）；**2 组可抽公共查询层但收益很低**（`/articles`、`/articles/{id}`，差异在鉴权与响应契约，不在 SQL）；**3 组是"同名不同义"**（`/appointments`、`/questions`、`/dashboard/stats`，角色、数据范围、响应结构都不同），强行合并会破坏 ACL 或前端契约。

**结论三（真正的重复在别处）**：教师端有**两套聚合实现**——`teacher.py:561-691` 的内联版本和 `app/teacher_analytics.py:9-45` 的共享版本（后者被 `/api/advanced-teacher/dashboard/metrics` 使用）。而 `GET /api/teacher/dashboard/stats` 在本仓库**前端、测试、文档、脚本中均无调用方**。另有两个教师文章端点同样无人调用（见 §2.3）。

**建议优先级**（本轮全部不动手）：

| 阶段 | 内容 | 收益 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| P0 | 从 core 依赖移除 `pymysql`，纠正 `.env.example` 的 MySQL 模板 | 小 | 低 | 可先做，需 Lead 批 |
| P1 | 文章 legacy 列表/详情抽公共查询函数 | 小 | 低 | 可选，不急 |
| P2 | 阅读量/幂等逻辑从 `student.py` 下沉到 service | 中（文件职责） | 中（测试直接引用私有符号） | 需「测试」同步改测试 |
| P3 | 教师聚合与无调用方 legacy 端点收敛 | 中（可删约 131 行死代码） | 中（是否存在仓库外客户端未知） | 需 Lead + 用户确认 |
| P4 | `/appointments`、`/questions`、`/dashboard/stats` | — | — | **明确不合并** |

## 1. 依赖残留核实

### 1.1 结论表

| 依赖 | 声明位置 | 仓库内实际引用 | 判定 |
| --- | --- | --- | --- |
| `pymysql` | `backend/requirements-core.txt:7` | `backend/create_db.py:1,4`（旧建库脚本，第 4 行含硬编码数据库账号与明文口令，此处不抄录）；`backend/.env.example:3`（MySQL 连接模板）；`backend/app/` 内 0 处 | **历史残留，可移除** |
| `python-docx` | `backend/requirements-core.txt:14` | `backend/app/routers/advanced_teacher.py:11-13`（模块顶层 import）、`:188`、`:230`（两个 DOCX 导出端点）；`backend/tests/test_student_assignments.py:20`、`backend/tests/test_support_workflow.py:17` | **真实运行时依赖，必须保留** |

### 1.2 `pymysql`：残留，但牵连两处需要一起处理

1. **应用代码不引用**。`backend/app/` 全目录对 `pymysql` / `mysql+` 的搜索结果为空；数据库入口 `backend/app/database.py:6-17` 只是通用 `create_engine(DATABASE_URL)`，SQLite 才加 `check_same_thread`（第 14 行）。`backend/app/models.py:308` 只有一处 `sqlite` 方言钩子，没有 MySQL 分支。
2. **唯一代码引用是旧脚本**。`backend/create_db.py:1` import `pymysql`，第 4 行用硬编码账号口令连本机 MySQL 建库。`docs/test/本地数据库与登录独立复核.md:17` 已明确该脚本"本轮不得运行，也不得作为部署路径"；`docs/ops/本地数据库部署与登录.md:37` 同样写明不使用旧 `init_db.py` 或 `create_db.py`。
3. **环境变量模板仍在误导**。`backend/.env.example:3` 的 `DATABASE_URL` 仍是 `mysql+pymysql://...` 模板，与本项目实际使用的 SQLite 和 `docs/ops/` 中的本机部署工具不一致。照模板配 MySQL 的人会真的需要 `pymysql`，所以**只删依赖不修模板，等于把坑留给下一个人**。
4. **移除后的行为**：若某台机器仍保留 MySQL 连接串，删掉 `pymysql` 后应用会在 `backend/app/database.py:17` 抛 `RuntimeError: DATABASE_URL could not initialize the configured database driver`，属于 fail-closed，可接受，但必须写进发布说明。

**建议动作（P0，本轮未做）**：
- 删除 `backend/requirements-core.txt:7`；
- 把 `backend/.env.example:3` 的模板改为 SQLite 示例（只改变量默认值，不读真实 `.env`，变量名 `DATABASE_URL` 不变）；
- `backend/create_db.py` 建议删除或移入归档目录（含明文口令，不建议继续留在仓库根部）；该动作涉及删除文件，需 Lead 明确批准；
- 若确实要保留 MySQL 作为部署目标，另建 `backend/requirements-mysql.txt` 单列 `pymysql`，并标注"未验收"，不要放在 core 里。

> 依赖链提醒：`backend/requirements.txt`、`backend/requirements-test.txt`、`backend/requirements-optional.txt` 都 `-r requirements-core.txt`，所以只改 core 一处即对全部入口生效。

### 1.3 `python-docx`：不是残留，不能挪到 optional

- `backend/app/routers/advanced_teacher.py:11` 是**模块顶层** `from docx import Document`，第 12、13 行同文件顶层 import `docx.oxml.ns`、`docx.shared`。
- `backend/app/main.py` 的 `include_router` 区无条件挂载 `advanced_teacher.router`（前缀 `/api/advanced-teacher`），模块在应用启动时被导入。**缺包 = 整个 API 起不来**，不是"只有导出功能不可用"。
- 实际业务用途明确：`advanced_teacher.py:182-213`（合规报告 DOCX 导出）、`:216-268`（单个已分配学生记录 DOCX 导出），第 188、230 行实例化 `Document()`。
- 两个测试也直接解析 DOCX：`backend/tests/test_student_assignments.py:20,154`、`backend/tests/test_support_workflow.py:17,278,284`。

**结论**：保留在 core。若未来只想让测试装它，必须同时把 `advanced_teacher` 改成懒加载 import，否则启动即失败——这是另一个独立改动，不建议顺手做。

### 1.4 复现命令（只读）

```powershell
# pymysql 全仓引用
Get-ChildItem -Recurse -File -Include *.py,*.txt,*.md,*.example backend |
  Select-String -Pattern 'pymysql|mysql\+'

# docx 在应用内的引用
Get-ChildItem -Recurse -File -Filter *.py backend\app |
  Select-String -Pattern 'from docx|import docx'

# 数据库入口
Select-String -Path backend\app\database.py -Pattern 'DATABASE_URL|create_engine|check_same_thread'
```

## 2. 六组接口逐组对照

六组路径相同、前缀不同（`/api/student` vs `/api/teacher`），FastAPI 不会冲突（两个 router 各自挂载，`main.py` 分别 `include_router`）。但"同路径"不等于"重复实现"，逐组看代码后分三类。

### 2.1 对照总表

| # | 路径 | 学生端 | 教师端 | 关系判定 |
| --- | --- | --- | --- | --- |
| 1 | `/articles/page` | `student.py:1000-1010`，无鉴权，直接 `page_articles(...)` | `teacher.py:957-969`，`check_teacher_role` 后同样 `page_articles(...)` | **字面重复**：10 行鉴权壳 + 同一 service |
| 2 | `/articles` | `student.py:1013-1019`，`List[schemas.ArticleResponse]`，叠加阅读量缓存 | `teacher.py:972-975`，无 `response_model`，返回原始 ORM，无阅读量处理 | 同查询、不同鉴权与契约 |
| 3 | `/articles/{article_id}` | `student.py:1021-1028`，同上，404 文案 `Article not found` | `teacher.py:977-983`，同上 | 同查询、不同鉴权与契约 |
| 4 | `/appointments` | `student.py:312-335` POST 创建（校验显式分配的教师）；`:337-352` GET 自己的，返回 `teacher_name`/`location` | `teacher.py:693-718` GET 自己的 + 分配学生，返回 `student_name`/`teacher_avatar`/`created_at`；`:720-732` 改状态 | **同名不同义**，不合并 |
| 5 | `/questions` | `student.py:1234-1248` POST 提交（`/questions` 与 `/questions/ask` 双装饰器）；`:1250-1269` GET 自己的，带 `response_state`/`assigned_teacher_count`/`answered_by` | `teacher.py:278-301` GET 分配学生的，包 `{"status","data"}`；`:304-331` 回答并写 `support_workflow_events` | **同名不同义**，不合并 |
| 6 | `/dashboard/stats` | `student.py:46-89` 个人情绪指数、测评数、红能量、预约数、树洞词云 | `teacher.py:561-691` 分配学生 KPI、风险分布、7 日情绪趋势、聊天词云、`warnings` | **完全不同的两套指标**，仅路径同名 |

### 2.2 为什么只有第 1 组算重复

- 第 1 组是唯一"同一实现、两个入口"的情况，且公共层**已经存在**：`backend/app/services/article_catalog.py:30-70` 的 `page_articles`。两个路由只是鉴权壳不同（学生端公开、教师端要角色），**保持两个薄壳是正确的**，硬合成一个 router 反而要在同一函数里分支鉴权，更差。
- 第 2、3 组数据源相同（`models.Article`），但差异在**鉴权**（学生端完全公开、教师端 `check_teacher_role`）和**响应契约**（学生端有 `response_model`，教师端没有）。SQL 本身只有一行 `order_by`，抽公共层只能省 2-3 行，收益极低。注意：学生端 `_read_article_views_cached`（`student.py:884-888`）当前**等价于直接读数据库值**，只是顺手写进程内缓存，所以两侧 `views` 实际一致——这意味着"抽查询层"不会改变数据，但也救不了多少代码。
- 第 4、5、6 组的范围由 ACL 决定：学生端 `current_user.id`，教师端 `assigned_student_ids(...)`。`AGENTS.md:30` 明确"教师只能查看分配给自己的学生"且"禁止把自由填写的 `advisor` 字段当 ACL"，`docs/team/进度看板.md:326` 同口径。这类差异是**刻意的安全设计**，不是可消除的重复。合并这三组 = 把两套 ACL 揉进一个函数，收益为负。
- 契约层面有测试钉死：教师 `/questions` 的 `{"status","data"}` 被 `backend/tests/test_support_workflow.py:99-101` 直接按 `["data"][0]["id"]` 断言；前端 `src/views/teacher/SupportWorkspace.vue:183-185` 的 `payloadRows` 依赖 `response.data?.data`。改成学生端数组形状会同时打破测试和页面。

用 `Get-ChildItem -Recurse` + `Select-String` 扫了 `src/`、`backend/tests/`、`docs/`、`scripts/`，以下端点**在本仓库内 0 调用方**（仓库外客户端未知）：

| 端点 | 前端 | 测试 | 替代/说明 |
| --- | --- | --- | --- |
| `GET /api/teacher/dashboard/stats` | 0 | 0 | 教师前端实际用 `/api/advanced-teacher/dashboard/metrics`（`src/views/teacher/AdvancedDashboard.vue:352`、`backend/tests/test_student_assignments.py:143`） |
| `GET /api/teacher/articles` | 0 | 0 | 前端只用 `/articles/page` + POST + DELETE（`ContentManagement.vue:192/246/266`） |
| `GET /api/teacher/articles/{article_id}` | 0 | 0 | 同上 |
| `GET /api/student/articles` | 0 | 2 处：`test_article_catalog_api.py:167`、`test_content_catalog.py:237` | 兼容端点，测试在测，**保留** |
| `POST /api/student/questions/ask` | 0 | 2 处：`test_support_workflow.py:93,139` | 与 `POST /questions` 同函数双注册（`student.py:1234-1235`），**保留** |

两套教师聚合的具体位置：

## 3. 合并方案（条件方案，按收益排序）

### 3.1 设计原则

1. **路径与鉴权不动**：任何合并都保持 `/api/student/*` 公开、`/api/teacher/*` 角色校验的现状；不改前端请求地址。
2. **ACL 不进公共层**：公共层只做纯查询/纯计算，接收 `student_ids` 或 `teacher_id` 作为参数，不自己推导权限。
3. **响应契约不统一**：学生端与教师端的 JSON 形状分别由各自测试钉死，不追求"一个模型两处用"。
4. **先加测试再移代码**：移动前先在 `backend/tests/` 补一条针对现状的契约断言（「测试」owner），再移。

### 3.2 P1：文章 legacy 列表/详情抽查询函数（可选）

在 `backend/app/services/article_catalog.py` 增加两个纯查询函数，学生/教师两个 router 各保留自己的鉴权与 `response_model`：

```python
def list_articles(db: Session) -> list[Article]:
    return db.query(Article).order_by(Article.created_at.desc()).all()

def get_article(db: Session, article_id: int) -> Article | None:
    return db.query(Article).filter(Article.id == article_id).first()
```

改动点：`student.py:1013-1028`、`teacher.py:972-983` 各换成一次调用，其余不动。`_ensure_article_views_initialized`（`student.py:963-965`，当前是空兼容钩子）与 `_read_article_views_cached` 留在学生 router。

- **收益**：小（约省 6-8 行，SQL 只出现在一个地方）。
- **风险**：低。教师端返回原始 ORM、学生端走 `ArticleResponse`，这点差异保持不变即可。
- **调用方改动**：0。路径不变。

### 3.3 P2：阅读量/幂等逻辑下沉（推荐做，但需「测试」配合）

`student.py` 里与"学生"无关的阅读量逻辑约 120 行，建议移到新文件 `backend/app/services/article_views.py`：

| 现位置 | 内容 |
| --- | --- |
| `student.py:549` | `ARTICLE_VIEW_DEDUP_WINDOW_SECONDS` |
| `student.py:874-876` | `_generate_initial_article_views` |
| `student.py:879-888` | `_touch_article_view_cache` / `_read_article_views_cached` |
| `student.py:891-932` | `_cleanup_view_idempotency` / `_consume_view_token` / `_consume_view_token_expiry` / `_release_view_token` |
| `student.py:935-943` | `_is_sqlite_lock_error` |
| `student.py:963-997` | `_ensure_article_views_initialized` / `_increment_article_views_atomic` |
| `student.py:1031-1061` | 路由 `track_article_view`（可留 router，只调 service） |

- **收益**：`student.py` 从 1269 行减去约 120 行，职责更清楚；将来若教师端也要"阅读量"或后台任务复用，不用再复制。
- **风险**：中。`backend/tests/test_article_view_counter.py` 直接 import 私有符号并断言：第 69 行 `student.ARTICLE_VIEW_IDEMPOTENCY.clear()`、第 90/205/257 行 `student._increment_article_views_atomic(...)`、第 100-102 行 `student._consume_view_token(...)`、第 228 行 `student.ARTICLE_VIEW_IDEMPOTENCY`。移动后这些引用必须由「测试」同步改成新模块，否则测试直接 ImportError。
- **调用方改动**：仅测试；前端与路由路径不变。

### 3.4 P3：教师聚合与无调用方端点收敛（需 Lead + 用户决策）

三个方案，按激进程度：

| 方案 | 做法 | 影响 | 建议 |
| --- | --- | --- | --- |
| A 保守 | 保留 `GET /api/teacher/dashboard/stats`，响应头加弃用标记/文档标注，下个版本再删 | 无破坏 | **推荐** |
| B 中等 | 把 `teacher.py:561-691` 换成 `teacher_analytics.dashboard_payload` 薄壳 | 响应结构整体变化，前端无调用但仓库外未知 | 不推荐，除非确认无外部客户端 |
| C 激进 | 直接删 `teacher.py:561-691` 和两个教师文章 GET 端点 | 删约 150 行；破坏未知外部调用 | 需用户确认后由 Lead 执行 |

注意：方案 B 不是"去重"，而是"换接口语义"——两套 payload 字段名完全不同（`kpi`/`risk_distribution`/`word_cloud` vs `realtime_stats`/`funnel_data`/`emotion_trends_7d`），硬换会制造新的契约问题。

### 3.5 P4：明确不合并的三组

| 组 | 不合并理由 | 若合并会发生什么 |
| --- | --- | --- |
| `/appointments` | 学生"创建/查看自己的"，教师"查看分配学生/改状态"，响应字段不同 | 一个函数里出现两条 ACL 分支，`assigned_student_ids` 一旦漏写就是越权 |
| `/questions` | 学生读自己的、教师读分配学生的；教师返回 `{status,data}` | 打破 `test_support_workflow.py:99-101` 与 `SupportWorkspace.vue:183-185` |
| `/dashboard/stats` | 两套完全不同的指标集 | 无意义，等于重写其中一个接口 |

## 4. 风险清单

| # | 风险 | 触发点 | 缓解 |
| --- | --- | --- | --- |
| 1 | **越权** | 把教师 ACL 过滤与公共层合并时漏掉 `assigned_student_ids` | 公共层只收 `student_ids` 参数；每次改动跑 `test_w2_security.py`、`test_student_assignments.py`、`test_support_workflow.py` |
| 2 | **契约破坏** | 给教师端点补 `response_model` 或统一 JSON 形状 | 以现有测试断言为准；前端 `payloadRows` 同时兼容 `{data}` 与数组，但测试只认一种 |
| 3 | **阅读量行为变化** | P2 移动代码时顺手"优化"幂等/重试 | 原样搬移，不改逻辑；`test_article_view_counter.py` 全跑 |
| 4 | **启动失败** | 删 `pymysql` 后仍有 MySQL 连接串 | 发布说明写明 fail-closed；`.env.example` 同步改 SQLite |
| 5 | **测试私有符号** | P2 移动后 `test_article_view_counter.py` 引用失效 | 由「测试」同步改 import，后端不交叉改 `backend/tests/` |
| 6 | **文档 owner 越界** | 本文件位于 `docs/design/`（前端 owner） | 由 Lead 本轮明确指派；只写这一个文件，`docs/README.md` 登记仍由 Lead 执行 |
