# 文章服务端分页接入

> owner: B / Lead ｜ version: 1.1 ｜ status: 前端技术通过 ｜ updated: 2026-10-26

## 目标与范围

学生文章列表和教师内容管理使用服务端筛选与分页。两页共享 `useArticleCatalog`，不会下载全库正文，也不会在浏览器重新筛选整库。详情继续使用原 `/article/:id` 路由；新增文章仍使用既有 POST，删除仍使用既有 DELETE。教师档案列表与编辑流程未调整。

## 页面行为

- 搜索输入最多100个字符，变化后立即回到第一页，300ms后发送请求；新输入会中止旧请求并使其迟到响应失效。
- 分类或排序变化立即回到第一页并请求；直接翻页立即请求。分类和搜索词变为无结果时显示匹配空态；全库为空时显示无文章提示。
- 请求期间清空旧页内容，筛选控件保持可操作；请求失败显示重试入口，重试沿用现有筛选条件。
- 服务器返回页码作为最终页码，支持删除当前页最后一条后服务端夹紧页数。
- 教师列表在请求中或失败时隐藏旧总数分页；空列表按当前搜索/分类状态区分“无匹配结果”和“尚无文章”。
- 教师新增成功后重置搜索和分类到第一页并刷新；学生收到阅读量更新时更新当前页，按阅读量排序时重新请求排序结果。

## 接口契约

页面请求 `GET /api/student/articles/page` 或 `GET /api/teacher/articles/page`，参数为 `page`、`page_size`、`q`、`category`、`sort`。默认页大小12；页面层只接受 `newest`、`most-read` 排序。响应必须包含 `items`、`total`、`page`、`page_size`、`categories`；列表项不得含正文 `content`。类别列表来自服务端全库有效分类。无效响应会进入错误态，不显示旧列表。

## 验证

定向 composable 测试覆盖搜索 debounce、分类/排序回第一页、迟到响应竞态、服务端页码夹紧不触发请求循环、失效分类复位及一次刷新、响应结构校验、卸载时中止请求。素材来源门禁也覆盖新增 composable 与页面。

完整前端22项测试、两视口30项文章交互和38个生产包页面通过；前次全新QA库实际注册、登录、文章读取与刷新两视口通过。最新跨日复验受Windows回环访问拒绝及Vite代理EACCES阻塞，当前完整集成门禁未通过。命令、后端回归与中间失败统一见[文章分页与预览验收](../test/文章分页与预览验收.md)，此文档不替代整体上线门禁。
