# 前端优化工作流

> owner: A / Lead ｜ version: 1.0 ｜ status: 实施完成，验收见测试记录 ｜ updated: 2026-10-24

本轮按用户“自己设计工作流，使用多agent模式完成前端优化”执行。起点 `4fcdebc`，分支 `codex/frontend-experience`，开工工作树干净。目标是让现有学生和教师工作更容易完成，沿用“温暖、有陪伴感、偏人文”的素材库。范围是现有19个叶页面及其共享框架；没有新增业务接口、依赖或角色。

## 工作流与文件分工

| 阶段/任务 | 唯一执行者与范围 | 输出/门禁 |
| --- | --- | --- |
| 1. 盘点与基线 | Lead：路由、旧构建、合成API截图 | 冻结Git起点，19路由×1440/390两视口，保留原始结果 |
| 2. FE-SHELL | Luna：两端Layout、`business.css`、布局说明 | 桌面分组与手机抽屉，共享表格/表单/弹窗；不引入图表引擎 |
| 3. FE-STUDENT | Luna：学生8页，排除Layout | 首页行动入口、预约/留言/阅读/聊天/报告/测评/树洞状态及响应式 |
| 4. FE-TEACHER | Luna：教师7页，排除Layout | 预警与跟进优先、列表/个体档案、表单和状态反馈 |
| 5. FE-SHARED | Lead：AuthShell、登录/注册、文章详情 | 标题层级、选填资料分组、文章加载失败恢复和异步清理 |
| 6. FE-REVIEW | 未参与本轮实现的另一Luna：只读代码/独立复核文档 | 不把作者自测当作独立评审；发现阻断交回唯一owner修复 |
| 7. 整合验收 | Lead：隔离构建/浏览器、自动化、团队记录与Git | 生产包真实渲染、键盘/窄屏/恢复交互、冷加载预算、素材源和目录卫生 |

所有子代理使用 `gpt-6-luna`，依用户最新模型要求。每张任务消息声明编号、输入、唯一写入范围、验证与交接，禁止代理暂存/提交/换分支。并行阶段互不改写文件；冻结后Lead接管整合。评审发现移动抽屉焦点留在背景，FE-SHELL返回修复，独立角色再次检查，然后进入浏览器验证。

## 设计约束与采用的技能

本轮阅读并采用本地 `frontend-design`、`ui-ux-pro-max` 与 `playwright`；前两者约束设计与交互，Playwright用于隔离QA。没有重新安装技能或依赖。UI UX Pro Max本地两次设计检索分别为wellness与education/task dashboard，命中的营销首页、用户评价、儿童字体及新色板不适合本产品，因此只采用语义结构、键盘焦点、响应式与反馈原则。实际页面继续以现有素材库和业务代码为准。

视觉源为 `src/styles/tokens.css`、`src/design/asset-registry.js`、`chart-registry` 与现有科研色卡。暖白承接阅读、品牌紫用于当前入口和主要操作、蓝绿图表语义保持。正文沿用微软雅黑/苹方/系统字体，品牌故事才用已有宋体衬线；没有远程字体、装饰emoji、新图标源或另造素材。所有新呈现的业务数据仍从原有受权限控制的API读取，图库合成数据不会进入业务代码。

信息密度按任务分层：页面标题与操作、需要处理的事项、趋势与明细。沿用token间距形成节奏，不用新增装饰卡片或配色区分每一种数据。桌面保留6组学生导航和5组教师导航，手机以抽屉完整呈现；长表格采用局部滚动。既有图表默认可见，移到相应行动区域之后，保持筛选、点击、resize与dispose。

```text
学生首页：页面标题 → 开始测评/预约/留言/助手 → 下一条真实预约 → 近期洞察与原图表
教师首页：分配范围告知 → 待审核预警 → 审核历史/跟进入口 → 统计与趋势
手机布局：导航+标题+主要操作 → 单列内容；抽屉打开后焦点进入并限制在导航内
```

| 登录/注册 | 每页一个主标题、说明、提交忙状态；注册资料标为选填，认证与密码规则保留 |
| 文章详情 | 加载骨架、失败原因与重新加载/返回列表；正文清洗、受保护附件和阅读量队列保留 |

| 预约咨询 | 老师与预约记录分别显示加载/失败/重试；不可预约说明关联到控件 |

| 匿名树洞 | 发布/列表状态、键盘和换行；不把显示匿名解释为平台不可识别 |
| 留言与答复 | 刷新、空态“写一条留言”聚焦输入、禁用空白提交；真实分配/回复状态 |

| 学生管理 | 列表加载失败/重试、局部横滚；仅分配范围 |
| 学生详情 | 数据状态、手机阅读与单生导出；原服务端ACL及导出路径保留 |

## 验收与可复跑

1. 用Git archive冻结起点并隔离构建，所有产物位于忽略的 `tmp/frontend-experience-20261024-bbc29a/`。通过只绑定loopback的静态预览访问旧/新构建；真实API返回503，浏览器测试逐请求拦截全部API、外部请求和WebSocket。
2. `capture-w2-ui.mjs`运行19页×1440/390，保存非空、图片、图标、未知API、错误、横向溢出、文章XSS与截图哈希。设 `W2_UI_EXTENDED=1` 启用新 `frontend-experience-checks.mjs`：导航键盘/背景隔离/路由关闭、320px、认证必填、文章与预约失败恢复、留言聚焦与审核/内容弹窗。
3. `check-frontend-loading.mjs`在全新浏览器上下文检查登录/注册两视口：gzip JS不超过250KiB，模块map证明未加载ECharts/zrender/Chart.js。字节预算不代表真实网络延迟或用户研究结论。
4. 跑现有Vitest、素材131项、来源检查与7个反例；不以提高chunk阈值替代性能检查。实际页面截图逐一抽查关键屏，存在问题则回到唯一owner修复并重建受影响构建。
5. 独立Luna只读复核变更及Lead证据，明确其亲跑命令与证据审阅范围。最后更新团队记录、索引，逐路径暂存、diff/文件卫生，Lead本地提交。

Browser插件与CUA在本轮工具中不可用，所以实际渲染使用现有Playwright/Edge新建无状态上下文，不连接用户浏览器会话。QA始终使用合成账号与响应，没有读取运行`.env`或数据库。完整结果及中间失败见[前端体验验收](../test/前端体验验收.md)，独立意见见[独立复核](../test/前端体验独立复核.md)。前端通过不代替尚未完成的目标容器、真实TLS、专业评测和校内上线批准。
