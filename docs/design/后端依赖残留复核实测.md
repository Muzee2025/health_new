结论沿用 `docs/design/后端重复接口合并方案.md`，本文件只补**可复现的实测证据**，不改依赖清单。

## 结论

| 依赖 | 判定 | 依据 |
|---|---|---|
| `python-docx` | **硬运行时依赖，不可移除** | 屏蔽 `docx` 后 `import app.main` **失败**，报错在 `advanced_teacher.py:8` |
| `pymysql` | **已清理，无残留** | 六份清单 0 处、`backend/app/` 0 处引用、`create_db.py` 已删、`.env.example` 已改 SQLite |
| RAG 那套（langchain/chromadb/…） | **关闭时完全不参与启动** | 屏蔽全部 RAG 包后 `import app.main` **成功** |

## 方法：屏蔽导入 + 对照检查

`grep` 只能证明"没有静态引用"，不能证明"运行时不需要"。所以用 `sys.meta_path` 屏蔽目标包后尝试启动，看是否真的失败。

**关键点：屏蔽器本身必须先被证明有效。** 第一次实现用了 Python 3.12 已废弃的 `find_module`，屏蔽器**静默失效**，于是 `docx` 也显示"导入成功"——差一步就得出"docx 不是硬依赖"的错误结论。正确写法是 `find_spec`，并且先对目标包做一次 import 断言它确实被拦住：

```python
BLOCKED = {'docx'}
class Block:
    def find_spec(self, name, path=None, target=None):
        if name.split('.')[0] in BLOCKED:
            raise ImportError(f'{name} blocked')
        return None
sys.meta_path.insert(0, Block())
try:
    import docx
    print('CONTROL FAILED: blocker is broken')
except ImportError:
    print('blocker works')
import app.main   # 真正的检验
```

## 实测结果

### python-docx（屏蔽 → 启动失败）

```
blocker works: docx blocked for dependency check
ImportError: docx blocked for dependency check
  File "app/routers/advanced_teacher.py", line 8, in <module>
    from docx import Document
```

`app/routers/advanced_teacher.py:8` 在启动路径上无条件 import，不是惰性的。从 core 删除会让应用起不来。它服务于 `/compliance/report`、`/students/{id}/export/docx` 两个导出端点。

### pymysql（屏蔽 → 启动成功）

```
blocker works: pymysql blocked for dependency check
app.main imports OK with pymysql blocked
```

六份清单（`requirements.txt` / `-core` / `-dev` / `-test` / `-optional` / `_rag`）均无 mysql 条目；`backend/create_db.py` 已由 `da2ba06` 删除；`.env.example` 的 `DATABASE_URL` 已是 SQLite。

**遗留**：本机 `.venv` 里仍装着 `PyMySQL 1.2.3`，属环境残留，不影响仓库与 CI（CI 按清单安装）。是否卸载由 Lead 决定。

### RAG（屏蔽 → 启动成功，且三种状态都优雅降级）

屏蔽 `chromadb`/`langchain*`/`sentence_transformers`/`FlagEmbedding`/`transformers`/`peft`/`unstructured` 后 `import app.main` 成功。`rag_service.py` 只在函数内惰性 import，模块顶层不碰任何 RAG 包。

开启 RAG 但后端不可用时，不抛异常、不崩溃，只把状态写进 `get_rag_status()`：

| 场景 | `state` |
|---|---|
| `RAG_ENABLED=false` | `disabled` |
| 开启但未配 `CHROMA_DIR` | `store_not_configured` |
| 开启、配了目录、`chromadb` 不可用 | `optional_backend_unavailable` |

三种情况 `ready` 均为 `False`，进程存活。这是正确的 fail-open 降级：检索不可用不应拖垮聊天主流程。

### core 清单完整性

13 个包全部可导入：`bcrypt` `fastapi` `jieba` `openai` `pydantic` `pyjwt` `python-docx` `python-dotenv` `python-multipart` `requests` `sqlalchemy` `starlette` `uvicorn`。
