# 前端分包与加载优化

> owner: B / W2-PERF-FE ｜ version: 1.1 ｜ status: 技术验收通过 ｜ updated: 2026-10-22

本轮从 `0d8b4be` 冻结基线开始，解决登录页静态加载完整 Element Plus 与 ECharts 的问题。原主包约 2,284.03kB。验收比较冷登录实际请求的全部 JavaScript raw/gzip 字节，不把改文件名、分拆入口或消除警告等同于首屏体积改善，也不作加载耗时承诺。

## 依赖入口

`main.js` 保留 Vue、路由、axios、品牌/控件 CSS、静态素材注册表及科研 CSS palette，移除 ECharts 与 Element Plus 全量安装。`provideGlobalConfig` 保留中文 locale；22 个使用 Element Plus 的 Vue 文件显式导入实际组件，使用 `v-loading` 的页面显式导入 `vLoading`。原程序式 Message、MessageBox、Notification 仍由调用页面导入。全量 CSS 保持原样，控制视觉和交互回归。

`LibraryIcon` 仍是已有素材登记图标的统一入口。`LibraryEmpty` 改为异步组件，只有出现业务空态时加载。原 approved 素材、manifest、许可、主题令牌、共享图库文件与历史截图不改；不引入新图库或依赖。

科研 palette 的 CSS 初始化拆为 `installBusinessPalette`，不需要图表引擎。图表主题仍调用现有库 adapter 的 `installBusinessCharts`，随图表 core 初始化，不另建第二主题。

| 懒路由所用 profile | 注册范围 |
| --- | --- |
| `src/design/charts/core.js` | ECharts core、Canvas、Aria、LabelLayout、既有业务主题 |
| `basic.js`：学生看板 | Line、Bar、Pie；Grid、Tooltip、Legend、Graphic、MarkPoint |
| `radar.js`：智能助手 / 风险因子组件 | Radar；Tooltip、Legend |

| `report.js`：学生报告 | Line、Bar、Pie、Heatmap、Graph、Radar；Grid、Tooltip、Legend、VisualMap、Graphic、SVG打印渲染器 |
| `confidence.js`：报告协同置信度 | Chart.js BarController、BarElement、CategoryScale、LinearScale、Tooltip、Legend |

各 profile 是对应懒路由的静态依赖，首次进入图表页才下载和注册。没有在组件挂载后新增异步图表加载步骤。`chart.js/auto` 已移除，登录页不预取 ECharts 或 Chart.js。图库继续使用自身原有完整 ECharts 入口，图库与业务共享视觉 helper 不变，八图示例与导出数据不动。

StudentDetail 模板实际没有 `chartRef` 容器；旧初始化从未显示图表。已移除约60行无效图表初始化及 resize 逻辑，不给该非图表页附加 ECharts 下载；对应新建后未采用的 detail profile 也已删除，未新增页面图表或改变真实接口。

Vite 只新增 `build.manifest: true` 供依赖审计；默认 Rollup 分包已达成目标，没有人为总 vendor、关闭预加载或提高 chunk 警告阈值。严格后端代理规则继续限定本项目 loopback 18080 与隔离验证 18081。

## 生命周期修复

- 学生看板请求未完成即离页时，旧 mounted continuation 可能在销毁后重新挂 resize。现以卸载标记阻止初始化与监听回挂，销毁后清图表引用。
- 报告等待模型元数据/报告响应时离页，旧 continuation 可能回挂 resize、打印、assistant 事件及轮询。现每个加载阶段检查卸载状态，清理 processing 重试 timer，图表初始化拒绝已卸载组件。
- 独立复核发现协同分析 done 的 3s 渐隐和 3.4s 关闭回调没有句柄。现保存句柄，重开分析及卸载时清理，回调同时检查卸载状态；已用真实浏览器后退验证两个 timer 取消。
- 风险因子组件在 nextTick 后复查容器与卸载状态；resize 使用实例 resize，卸载后不接受迟到请求并清引用。
- 学生详情保留数据请求卸载保护。智能助手、教师大屏原有会话取消/卸载保护保持。

以上只处理加载、图表释放和监听生命周期，不改变 API 字段、身份策略、真实数值、权限、量表、计算和导出规则。

## 可复跑的加载门禁

`npm run perf:build` 在新的 `tmp/frontend-audit` 构建，附模块来源与manifest；已有目录拒绝覆盖。`npm run perf:preview` 用同目录启动4185的gzip预览，绑定loopback、只读编译文件，API固定503且不代理到运行系统。再次审计应通过环境变量选择新的输出目录，不覆盖旧证据。

```powershell
# 终端一：选择新的目录，再构建与预览
$env:PERF_BUILD_OUTPUT = 'tmp/frontend-audit-new'
npm run perf:build
$env:PERF_PREVIEW_DIR = $env:PERF_BUILD_OUTPUT
npm run perf:preview
# 终端二：设置本机已有Playwright模块目录后执行检查
$env:LOADING_BUILD_DIR = 'tmp/frontend-audit-new'
$env:LOADING_BASE_URL = 'http://127.0.0.1:4185'
$env:LOADING_REPORT = 'tmp/frontend-audit-new-loading.json'
$env:LOADING_ENFORCE = '1'
npm run perf:check
```

有本地Playwright安装时直接解析包；否则用 `PLAYWRIGHT_MODULE_PATH` 指定已有包目录，缺失应明确报告，不自动安装。默认启用门禁，要求每个请求在模块来源中登记、冷认证页JS gzip≤250KiB且没有图表引擎；只有采集历史基线时才显式设置 `LOADING_ENFORCE=0`。它不替代HTTP/2、真实网络、LCP/FCP、CSS优化或业务回归。保持7项存量来源未核实素材隔离说明；本轮不处理后端和历史数据问题。
