本大纲记录系统的页面组织、核心任务与阶段性实施状态。v0.3的规划依据与历史结论保留；v0.4补录 SUP-FE 已落地的导航和求助闭环。Lead已完成两视口真实临时SQLite与38生产包页面回归，详见[本轮验收](../test/补齐任务验收.md)。其余标为规划的内容仍未实现或未获业务确认。

## 1. 阅读方式与系统边界

本文统一使用三种状态，避免把规划当作已有能力：

- **现有代码实现**：当前路由、模板或请求逻辑中可以找到；是否依赖外部服务另行说明。
- **建议调整**：在现有页面上完善层级、命名、状态和去向，实施时仍须验证接口与权限。
- **新增规划／需支持**：当前没有完整页面或业务闭环，必须先落实后端、运营或专业业务口径。

优先级：P0为会误导用户、影响权限或业务结果的缺口；P1为核心任务顺畅完成；P2为增强能力。优先级不是已承诺的工期。

**现有代码实现**仅有学生、教师两种业务角色。教师按明确分配关系访问学生，公开教师资料与可预约权限分开；辅导员姓名不是授权依据。本地role用于导航体验，真实权限由后端核验。

**现有记录**说明本机数据库副本与认证链路已完成本地技术验证，但真实模型配置、校内运行流程和公网生产上线仍有待办。本大纲不把这些写成已经投入正式运营。

目标用户及其任务：

| 用户 | 来到系统要完成什么 | 界面首先应回答什么 |
| --- | --- | --- |
| 学生 | 了解近期状态、完成测评、倾诉、找资源、预约支持 | 我现在可以做什么，记录在哪里，下一步去哪里 |
| 已分配教师 | 查看待处理预警与预约、核实学生情况、记录干预 | 哪件事需要先处理，我能看哪些学生，处理后怎样留痕 |
| 校内维护／业务负责人 | 确认分配、联络、内容与服务口径 | 当前没有相应运营后台；所需流程先作为待定支撑条件 |

不以AI情绪标签、风险提示、趣味测验或单次量表分数替代专业诊断；具体文案和处置规则需专业人员确认。

### 2.4 学生目录：比较5项与6项后推荐6项

| 方案 | 一级分类 | 取舍 |
| --- | --- | --- |
| 5项备选 | 首页／自助成长／找支持／匿名树洞／我的 | “找支持”下放预约与AI，入口更少，但多一层寻找，人工预约与即时AI的响应预期更易混淆 |
| **6项推荐** | **首页／自助成长／预约咨询／智能助手／匿名树洞／我的** | 将测评与科普归资源任务，报告归本人记录；保留预约与AI的直接入口，也不把社区混入私密记录 |

推荐结构如下。括号内为已有页内模块或后续组织提案，不是新增独立页面。

```text
首页 → /student/dashboard（下一次预约、支持入口、近况摘要）
自助成长 → 默认 /student/test
  ├─ 心理测评 → /student/test（开始作答与本次结果）
  └─ 心理科普 → /student/articles → /article/:id（分类、阅读）
预约咨询 → /student/appointments（找老师、可预约时段、我的预约记录）
智能助手 → /student/advanced-chat（日常／咨询会话、会话列表）
匿名树洞 → /student/treehole（社区首页、我的发布、收藏三个现有tab）
我的 → 默认 /student/report
  └─ 我的心理报告 → /student/report（对话来源、详情、打印）
```

“自助成长”放开始测评与阅读资源，不放既往个人报告；“我的”首先用已有报告承接，不虚设个人中心首页。我的预约、已保存会话可提供跨功能快捷链接，分别返回预约／助手原页，既不复制记录库也不重复计页。
首页仍保留“开始心理测评”快速入口；分组展开后直接显示“心理测评／心理科普”文字入口，不藏在泛化图标或不明“更多”里。
树洞的“我的发布／收藏”仍留在社区内：它们关联对外展示的社区内容，不包装成只有本人可见的私密日记。科普文章也不混入个人心理档案。
已落实：Questions从无入口改为预约／助手次入口；未新增学生一级菜单。该入口以学校分配教师可见并返回本人可见答复为前提，不提供响应时限承诺。

**点击与选中规则（建议调整）**：点击一级名称直接进入上面的默认已有路由；有两个真实子页的“自助成长”提供独立展开控件选择子页，不强迫先经过一个新父页面。“我的”只有报告时可直接进入，不展示空的二级清单。
路由到`/student/test`或`/student/articles`时高亮“自助成长”，到`/student/report`时高亮“我的”；学生阅读`/article/:id`时归“自助成长”。跨功能快捷链接进入预约／助手后高亮其目标页归属组，不按跨链来源选中，也不出现两个一级同时选中。
预约／会话／树洞记录的跨链只返回其已有页面；当前未实现的tab、锚点或query定位不承诺直达某条记录、收藏页或恢复筛选，最终高亮按目标页归属。
桌面侧栏与手机保持同一分类、名称、顺序和默认去向；手机可沿现有横向导航配二级展开，或另评审折叠菜单，不强行把6项挤成底部图标条，也不让“更多”隐藏预约或AI的含义。
预约筛选维度可以参考高校流程，但当前只具备教师卡片和时段；按地址／日期筛选、须知同意及前置评估均须独立验证字段与流程，不能因对标就宣称已支持。

### 2.5 教师目录：5项工作任务与二级内容

| 推荐一级 | 二级子页／页内模块 | 点击进入的已有路由与边界 |
| --- | --- | --- |
| 工作台 | 待处理预警、范围说明；审核要求填写原因并回读真实历史，概况、趋势、聚合导出仍为次级模块；“求助与跟进”二级入口 | `/teacher/advanced-dashboard`→`/teacher/support`；历史无审核事件时标明不可追溯，不显示虚假的“已移入历史”结果 |
| 我的学生 | 分配学生列表→学生档案；档案内时间轴、预约、对话摘要、干预记录；个体 DOCX 按学生详情单生 endpoint 导出 | `/teacher/students`→`/teacher/student/:id`；教师聚合导出仍只在聚合大屏 |

| 内容与档案 | 文章维护；我的咨询档案 | `/teacher/content`内两个现有tab；拟将“心理老师管理”改名为本人档案，不新增全校教师管理权限 |

一级点击直接进入对应已有页；学生详情高亮“我的学生”，求助与跟进是工作台的二级路由。内容tab选择仍在同一页，不建立空壳父路由；若需从导航直达某tab，须先补前端tab定位，不假定当前已支持query参数。
预警核实、学生档案、预约、内部跟进和干预记录通过保留学生上下文的操作互达；趋势、导出、筛选和弹窗不独立挤入一级目录。账号设置、消息通知仍无现成页面；问答答复已在工作台二级区完成，不因“主流产品有”就先显示无效菜单。

### 2.7 公开门户与登录后工作区分层

**现状**：本项目没有独立公开科普栏目，文章详情也要求登录；“教师公开资料”指已登录学生可查看的资料范围，不等于互联网公开门户。现有匿名树洞也不是无需认证的公共站点。
**未来门户规划／需支持**可参考高校公开网站，组织“服务介绍、服务团队、咨询须知、科普、求助与联络”；危机说明、课程与活动仅在真实责任人与内容具备后建设。所有公开内容先审查可见字段、许可与发布流程，不能把学生文章／资料接口直接去认证。
门户负责解释“有什么、如何获得服务”，登录后工作区负责本人记录和分配任务；门户的“进入学生空间／教师空间”再走现有认证与权限，不能共享公开缓存里的个人报告。
**最终建议**：学生采用6组、教师采用5项高频工作区，先复用现成路由；公共内容、人工服务、AI会话、社区互动和本人记录各有明确归属。该选择来自本项目的能力、隐私与使用任务约束，不是照抄某一家网站，也不等于已完成改版。

## 4. 学生首页：先给行动，再解释近况

**现有代码实现**以五组统计图为主体，学生Layout固定提供“新增预约”。标题“心理健康数据看板”是现状，“我的近况／首页”是命名提案。

**建议调整**采用以下顺序，不增加虚构的欢迎指标、连续打卡或未读数字：

```text
页面标题：我的近况                 主要动作：找支持／预约
下一次预约或明确空态               查看预约、取消／进入预约页
我想做什么：完成测评｜聊一聊｜读一篇科普
近期记录摘要：日期、量表／对话来源、进入相应详情
趋势与对比：按需展开，不混淆量表分数和AI情绪
树洞与积分：次级区域，不以积分代表心理健康水平
```

1. 已有下一次预约字段时展示真实时间、地点与状态；无记录只提供去预约，不生成“待办”。
2. 测评、报告、助手是不同任务，按钮分别去既有路由；不以一颗“健康总分”合并不同来源。
3. 首次使用只解释可做的事情；“继续上次测评”须先验证本地进度与当前身份的一致性，属于待实现动作。
4. 趋势默认最近有效区间，仍可7/30/90天切换；日期和数据缺口可见，加载失败不补演示数据。
5. 持续可达的求助入口属于新增规划；展示真实校内联络方式与服务时间前需运营确认，不能编造号码或全天候响应承诺。

验收重点：没有历史的新学生也能理解下一步；有预约的学生无需先滚过多张图才能找到咨询安排。

## 5. 教师工作台：待办与学生处置优先

**现有代码实现**先展示指标与图表，再显示待审核预警。聚合只统计明确分配学生；楼宇没有可信字段时为空。

**建议调整**保持当前路由，按以下结构组织：

```text
工作台标题＋可见范围＋更新时间       导出预警审阅报告（次操作）
待处理预警：时间、对象、线索、可执行动作

```

1. 已有预警列表优先重排；“今日待办／逾期／已联络”计数若没有统一时间口径和字段，不先展示。
2. 无分配显示“当前尚未分配学生”；这是范围状态，不能用全校数据填充或从advisor猜归属。

5. 当前“联络说明”只解释未提供联络方式；真正的联络、确认、升级与回访需校内流程和字段支持。

验收重点：教师能先处理一条真实待办，并在刷新后核对结果；无权限、无分配与无人处理必须有不同解释。

## 6. 关键任务闭环

### 6.1 测评—结果—报告／预约

- **现有代码实现**：测评大厅→逐题作答→本地计算结果→请求保存；可选AI解析，结束回大厅。保存失败会提示，但结果仍在页面。
- **建议调整**：结果页明确“已计算／已保存／保存失败待重试”；保存成功后显示“查看我的记录、预约支持、和助手聊聊”等准确去向。
- **新增规划／需支持**：测评历史详情与报告来源衔接；当前Report为对话驱动，不能宣称测评提交即自动生成此报告。重试幂等、测评适用性与解释口径需确认。

### 6.2 AI聊天与老师问答

- **现有代码实现**：助手支持会话与匿名不保存模式；Questions有学生提交、本人历史和教师答复；预约与助手可进入留言，教师在工作台二级区处理明确分配的学生问题。
- **已落实**：将“与AI聊聊”“向老师留言”明确分开；留言包含未分配、待回复、已回复、空／错和服务未启用状态。教师答复会回到学生本人历史。
- **新增规划／需支持**：通知、撤回／关闭与学校正式服务流程仍未接入；负责人和服务时间未落实前不承诺回复时效。
- **隐私边界**：聊天匿名开关不等于不认证或不调用模型服务；告知保存、传输与提供方范围需专门确认。

### 6.3 学生预约—教师处理

- **现有代码实现**：公开教师资料→can_book允许的时段→确认→本人记录；教师pending→confirmed→completed／cancelled；学生可取消。
- **已落实**：状态文案与动作采用后端`confirmed`；存量`approved`仅作为已确认展示的兼容值；已完成独立显示，不归入已确认。
- **新增规划／需支持**：改期、重复占位冲突、通知、取消截止和未到场规则；首页“修改”当前只跳预约列表，不是改期功能。
- **权限边界**：预约不自动建立教师可见关系；未分配、时段已满与服务未排班要分别提示。

### 6.4 分配学生—预警核实—干预—跟进

- **现有代码实现**：学校明确分配→教师查看其学生与预警→进入档案／添加干预→干预列表可查；教师新建学生会建立本人分配关系。工作台二级区可处理已分配留言、预警审核和内部跟进任务，学生详情使用单生导出endpoint。
- **建议调整**：每个动作携带正确学生上下文，并回到来源任务；记录保存后在列表与档案中可核对。
- **已落实**：预警审核记录原因并读取历史；历史不存在或读取失败会分别说明；跟进任务可创建、完成、取消并记录教师内部结果。
- **新增规划／需支持**：外部联系结果、正式负责人安排、复核与重开政策仍待运营确认；当前实现不宣称完整危机联络工作流。
- **隐私边界**：档案当前有按学生关联的对话及树洞汇总；“脱敏”只代表现有规则能力，不能承诺完整去标识或全校共享。

### 6.5 科普—阅读—内容维护

- **现有代码实现**：教师维护文章／附件→学生按分类阅读→详情和受保护附件下载；正文已净化。
- **建议调整**：读者看到来源、更新时间与附件状态；维护者能确认保存对象，不将无审核的文本包装为专业认证建议。
- **新增规划／需支持**：草稿、编辑、预览、审核、上下架与举报处理的权限和状态；当前不能称完整内容运营平台。

### 6.6 报告—打印／分享

- **现有代码实现**：学生报告有打印预览、浏览器打印；系统打印可由用户设备选择另存文件，但无独立PDF下载API。
- **现有代码实现**：原生share只发送标题／文字；不支持时复制当前页面地址。没有授权报告快照、到期或撤销能力。
- **建议调整**：先确认是否需要分享；保留前先准确标注“分享说明／复制页面地址”，不能暗示收件人可读本人报告。
- **新增规划／需支持**：若确需共享，须另定义接收者、范围、授权、到期、撤销与审计；个体教师导出也需明确学生对象协议。
