本轮安装全部用 `npm install --no-save`，`package.json` 与 `package-lock.json` 哈希前后一致（见第 7 节），没有替前端做依赖决策。

## 3. 规则集

### 3.1 ESLint（`eslint.config.js`）

组合：`js.configs.recommended` + typescript-eslint `recommended`（**只作用于 `**/*.ts`**）+ eslint-plugin-vue **`flat/essential`** + `@vitest/eslint-plugin` recommended。

- 为什么不是 `flat/recommended`：实测该预设会把模板格式规则一起带进来，`vue/max-attributes-per-line` 单独就 1,249 条、`vue/singleline-html-element-content-newline` 784 条、`vue/html-quotes` 273 条——和 Prettier 直接打架。规范的分工是 **ESLint 管正确性、Prettier 管格式**，所以用只含正确性规则的 `flat/essential`。
- 作用域：`src/**`、`scripts/**`、`public/sw.js`、`vite.config.js`；排除 `backend/`、`docs/`、`dist/`、`coverage/`、`tmp/`、`.venv/`、`deliverables/`、`scripts/archive/`。
- 目录级 globals：`src/**` 给 browser；`scripts/**` 给 node + browser（这些脚本用 Playwright，`page.evaluate()` 回调跑在浏览器里，只给 node 会误报 `document`）；`public/sw.js` 给 serviceworker + browser。
- 两条显式覆盖：
  - `no-unused-vars` 允许 `^_` 前缀（占位参数）；
  - `vue/multi-word-component-names` **关闭**：仓库既有 `Layout.vue / Login.vue / Dashboard.vue` 等 11 处单名单词组件，改名是重构决策不是 lint 修复；关闭后不阻塞对老文件的修改，等第二阶段再议。

### 3.2 Prettier（`.prettierrc.json` + `.prettierignore`）

```json
{ "semi": false, "singleQuote": true, "printWidth": 100,
  "trailingComma": "all", "arrowParens": "always",
  "endOfLine": "lf", "vueIndentScriptAndStyle": false }
```

参数依据（都是仓库实测，不是拍脑袋）：

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| `semi` | false | 71 个文件里只有 17 个出现行尾分号，无分号是主流 |
| `singleQuote` | true | 前端 import/字面量以单引号为主（191 处 import 抽样绝大多数单引号） |
| `printWidth` | 100 | 80 → 92 个文件被改 / +21,513 行；100 → 88 个 / +17,441 行；再往上收益递减。JS 现有 >100 的行占 11.4%，100 是改动最小的合理值 |
| `trailingComma` | all | `es5` + `arrowParens: avoid` 组合实测改动只少 11 行（+17,500 / −5,405），不值得为非默认值增加记忆成本 |
| `endOfLine` | lf | 与 `.editorconfig` 一致；实测只多 1 个“仅行尾差异”的文件 |

`.prettierignore` 排除生成物与文档：`docs/`、`backend/`、`dist/`、`coverage/`、`tmp/`、`deliverables/`、`src/assets/`、`public/assets/`、`package-lock.json`、`scripts/archive/`。

### 3.3 Ruff（`ruff.toml`）

- `target-version = "py312"`、`line-length = 100`。
- **必须显式 `select`**：Ruff 0.17.4 在**没有配置**时对本仓库报 **837 条**（RUF/SIM/PL/TRY/C4 一大批重构类规则），对存量直接不可用。本方案钉死为正确性集合：

```toml
select = ["E4", "E7", "E9", "F", "I", "B"]
ignore = ["B008"]
```

- `B008` 必须忽略：184 条全是 FastAPI `Depends()` 写在参数默认值里的惯用法，是误报。
- `per-file-ignores`：`backend/tests/**` 放宽 `B011`（`assert False` 换 `pytest.raises` 属测试风格）；`**/__init__.py` 放宽 `F401`（包导出）。
- `[lint.isort] known-first-party = ["app"]`：后端以 `app.` 为根包。
- 格式化：双引号（Python 现状双引号 5,209 行 / 单引号 425 行，与 Ruff 默认一致）；`docstring-code-format = false`（不重排 docstring 里的示例代码）。
- 行宽取 100 而不是 Ruff 默认 88：临时副本实测 88 → 82 个文件 / +8,742 −2,746 行；100 → 80 个文件 / +6,557 −2,326 行。少改 25% 的行，且与前端 Prettier 的 100 对齐。

### 3.4 `.editorconfig`

`utf-8`、`lf`、`space`、indent 2（py 4）、`trim_trailing_whitespace = true`（md 除外）、文件末尾换行。只影响**新输入**，不会重写任何现有文件。

## 5. 落地顺序（分阶段）

### 阶段 0（本轮，已完成）

只加 5 个配置文件 + 本文档；不碰任何源文件；基线全绿。产出物：

- `eslint.config.js`
- `.prettierrc.json`、`.prettierignore`
- `ruff.toml`
- `.editorconfig`

### 阶段 1：让工具“可被调用”，但不格式化（0.5 天，需前端/后端配合）

1. 前端在 `package.json` 加 devDependencies（版本见第 2 节）和 4 个 scripts（我不动 `package.json`，文件所有权归前端）：
   ```json
   "lint": "eslint .",
   "lint:fix": "eslint . --fix",
   "format": "prettier --write \"src/**/*.{js,ts,vue,css}\" \"scripts/**/*.mjs\" \"public/sw.js\" \"vite.config.js\"",
   "format:check": "prettier --check \"src/**/*.{js,ts,vue,css}\" \"scripts/**/*.mjs\" \"public/sw.js\" \"vite.config.js\""
   ```
   注意 `"format"` 不要写成 `prettier --write .`：那会把根目录 `README.md`、`index.html`、`package.json` 一起改掉，超出本轮范围。
2. 后端把 `ruff==0.17.4` 登记进 dev 依赖清单（建议新建 `backend/requirements-dev.txt`，由后端决定）。
3. CI 先只对**变更文件**跑 lint，不跑全量（CI 归测试）：
   ```bash
   CHANGED=$(git diff --name-only --diff-filter=ACMR "$BASE"...HEAD -- '*.js' '*.mjs' '*.ts' '*.vue')
   [ -z "$CHANGED" ] || npx eslint $CHANGED
   ```
   Windows 本地对应写法：
   ```powershell
   $changed = git diff --name-only --diff-filter=ACMR -- '*.js' '*.mjs' '*.ts' '*.vue'
   if ($changed) { npx eslint $changed }
   ```
4. 验收：`npx eslint .` 允许 62 条存量错误存在；变更文件必须 0 error。

### 阶段 2：按目录分批格式化（每批一个提交，每批跑基线）

原则：**先 JS/TS，再 CSS，再小组件，最后模板密集的大文件**。每批只动一个目录，改完立刻跑第 7 节的命令，数量不变才进下一批。

前端（建议 6 批）：

| 批次 | 范围 | 改动文件 | 风险 |
| --- | --- | --- | --- |
| F1 | `src/services/`、`src/composables/`、`src/utils/`、`src/router/`、`src/data/` | 24 | 低（逻辑文件，测试覆盖 12 文件） |
| F2 | `scripts/`（20 个 mjs） | 20 | 中（+6,961 行，是本次最大单块；这些是验收脚本，改完要重跑它们本身） |
| F3 | `src/styles/`（3 个 css）、`src/design/`、`src/components/` | 16 | 中（样式/图表注册，视觉回归靠浏览器验收） |
| F4 | `src/views/` 根目录（`Login/Register/NotFound`）+ `src/main.js`、`App.vue` | 5 | 中（登录页有安全契约测试） |
| F5 | `src/views/student/`（**排除** `Report.vue`、`AdvancedAiChat.vue`） | 约 8 | 中 |
| F6 | `src/views/teacher/` + `src/views/admin/` | 约 13 | 中 |
| F7 | `Report.vue`（1,928 行）、`AdvancedAiChat.vue`（1,392 行）、`vite.config.js`、`public/sw.js` | 4 | **高**，单独一批，只格式化不改逻辑 |

后端（建议 5 批，先 `--fix` 再 `format`，每批分开看 diff）：

| 批次 | 范围 |
| --- | --- |
| B1 | `backend/scripts/`（迁移/工具脚本） |
| B2 | `backend/app/models/`、`schemas/`、`utils/`、`dependencies/` |
| B3 | `backend/app/services/`（`rag_service.py` 除外，归 Lead） |
| B4 | `backend/app/api/` + `main.py` |
| B5 | `backend/tests/`；`backend/app/services/advanced_chat.py`（1,430 行）最后单独一批 |

`ruff check --fix` 与 `ruff format` **分两步、分别提交**：前者含 `F401` 删除未用 import，后者纯格式，混在一起无法审。`F401` 要人工过一眼（包 `__init__` 的副作用导入已用 per-file-ignore 保护，但业务模块里删 import 仍可能影响启动），必要时 `--unsafe-fixes` 禁用、逐条改。

### 阶段 3：CI 收口（归测试）

- 全仓库 `eslint . --max-warnings 0` + `prettier --check` + `ruff check` + `ruff format --check`。
- **行尾统一**：`.editorconfig` 已是 `lf`，但存量 68 个文件是 CRLF。建议 Lead 在阶段 2 完成后执行一次 `git add --renormalize .` 并加 `.gitattributes`（`* text=auto eol=lf`），否则今后每次编辑器保存都会产生整文件 diff。这是 Git 操作，按规则归 Lead。
- 门禁建议：先“仅变更文件”，稳定 1–2 周后再“全仓库”。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Vue 模板重排巨大（+6,774 行 / 25 个文件） | review 困难、和前端并行改动冲突 | 单独批次、单独提交；格式化前和后端/前端确认没有未提交改动；`git diff -w` 复核 |
| `scripts/` 一次 +6,961 行 | 验收脚本 diff 难读 | 单独一批，且这批改完必须重跑这些脚本本身的关键几项 |
| 68 个 CRLF 文件被编辑器整文件翻新 | 无意义 diff 污染历史 | 阶段 2 结束后统一 `renormalize`（Lead 执行），不要在阶段 1 提前做 |
| `F401` 自动删除“看起来没用的 import” | 包初始化/ORM 注册处可能启动失败 | `__init__.py` 已豁免；业务模块逐条人工确认；每批跑后端基线 |
| 大文件格式化冲突 | `Report.vue`、`AdvancedAiChat.vue`、`advanced_chat.py` 万一格式化出问题很难 review | 放最后；只格式化不改逻辑；单独提交；格式化后立刻跑基线 |
| 依赖版本坑 | `typescript@5.x` 会装不上 lint 栈 | 钉 `typescript@6.0.3`（见 2 节） |
| 与 Prettier 抢格式 | 若误用 `flat/recommended`，2,600+ 条模板规则会反复报错 | 已固定 `flat/essential`；禁止再引 `@vue/eslint-config-prettier` 之类叠加层 |

## 8. 本轮发现的问题（只记录，未修）

1. **`scripts/archive/legacy-dashboard-fragment.mjs` 不是 UTF-8**（GBK/ANSI），ESLint 报 `Parsing error`、Prettier 报 `Error occurred when checking code style`。已在 lint/format 两侧排除。建议前端转码或归档删除，否则该文件永远无法纳入规范检查。
2. **`src/design/chart-registry.js` 从 `docs/design/` 导入生产代码**（`chart-style.js`、`chart-options.js` 等 5 个文件、约 63 KB）。这让 `docs/` 既是文档又是运行时依赖，规范工具无法覆盖。建议前端在拆分阶段把这些文件迁进 `src/design/charts/`；迁移后 Prettier 会多覆盖 5 个文件（+1,676 行）。
3. **`.vue` 文件有 25/28 会被重排**，说明模板写法（多属性单行）与 Prettier 默认风格差异最大；如果前端团队不接受这种拆行风格，应在阶段 2 前决定：要么接受，要么把 `printWidth` 提到 120（预计少改约 15% 的行）——但不要改完再改回去。
4. **`docs/` 有 812 个文件、`deliverables/` 153 MB**，均不在规范工具作用域内（本轮刻意排除）；Markdown 是否纳入 Prettier（`proseWrap`）建议单独评审，不要和代码格式化混在一起。
5. 仓库根目录已有一批历史文档（`AGENTS.md`、`QUICK_START.md` 等），`docs/README.md` 索引登记需 Lead 维护，本轮未动。
