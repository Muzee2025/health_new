只做**可逆**动作，不删任何文件。

1. **移出 5 个 100% 冗余 ZIP**（§8.2，3.31 MiB）→ 上传到 GitHub Release 附件，仓库内改引用为 Release URL。
2. **不改** `docs/` 任何内容（证据链完整保留）。
3. **不删** 3 个文本重复的 PPTX 与 `optimized.pdf`（仅登记在册，等用户答辩结束后再定）。
4. 同批删掉 `ACKNOWLEDGED_OVERSIZED` 里对应条目的登记。**本方案涉及的 5 个 ZIP 全部 < 2 MB，都不在登记表内，所以 `ACKNOWLEDGED_OVERSIZED` 一条都不用改，`oversized` 不变。**
5. 改 3 处断链引用：`docs/test/Excel通用训练库验收_20261102.md:15`、`docs/test/excel-training-database-verification-20261102.json:36`（指向 `通用训练资料包.zip`）、`docs/ppt/six-chapters-20261029/README.md:33`（指向 `旧PPT提取包.zip` 且绑定 SHA256 `9de3853bfaca6ea011f19f66debab9150e818931988dbdc3ca7e41435edc93e1`）。

**收益**：仓库跟踪体积 160,216,095 → **156,742,030 B = 149.48 MiB**（−3.31 MiB）。clone 体积**基本不变**（blob 仍在历史）。

**风险**：低。所有成员可还原，引用可改，`check-repo.py` 不变。

### 方案 B（激进）

每类只留最新版，历史版本全部移出。

1. 执行方案 A 全部。
2. **移出 15 个非最新 PPTX**（16 个保留 1 个，建议 `六章答辩PPT_多智能体协作机制优化版_20261031.pptx`，或用户指定的 R6 正式稿）→ **25,002,330 B = 23.84 MiB**。
3. **移出 6 个非最新 DOCX**（9 个保留 3 个：策划书 + 计划书 + 申报书图表增强稿）→ **329,344 B = 0.31 MiB**。
4. **移出 `optimized/optimized.pdf`**（§8.3）→ **1,537,710 B = 1.47 MiB**。§8.3 里那两个 8 页 PPTX 已含在第 2 步的 15 个内，**不重复计算**。
5. 同步删 `ACKNOWLEDGED_OVERSIZED` 中已移出的条目（PPTX 4 条 + DOCX 2 条 + 18 页稿 1 条 = **7 条**，逐条核对后删）。

**收益**：仓库跟踪体积 **129,872,646 B = 123.86 MiB**（相对现状 −30.61 MiB，相对方案 A 再 −25.62 MiB）。

**算式**：`160,216,095 − 3,474,065（方案 A 的 5 ZIP） − 25,002,330（15 PPTX） − 329,344（6 DOCX） − 1,537,710（optimized.pdf） = 129,872,646`。

**风险**：中高。
- 历史 PPTX 是「用户可能要的答辩备选」，删除后需从 Release 下载才能取回。
- 需逐项确认「哪个是最新版」——本次实测已证明**文件时间戳全部是入库时间，完全不可用**，只能靠 `core.xml` + 文本比对 + `docs/` 状态描述三方交叉。**§5 的 3 个文本相同 PPTX 已证明「看起来不同版本、实际同一份稿」确实存在**，误判风险真实。

### 两套方案都不做的事

- **不重写 Git 历史**。理由见 `docs/ops/历史重写方案_20261113.md`：天花板仅 15 MiB，代价是全部提交 SHA 变化、19 分支 + 12 tag 作废、27 份文档的提交号引用失效。
- **不动 `docs/` 证据链**。
- **不动 `tmp/`**（不进 Git，与本目标无关）。
