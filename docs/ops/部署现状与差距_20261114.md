# 部署现状与差距

> owner: 部署 ｜ version: 1.2 ｜ status: 现状盘点完成；目标容器、正式 TLS 与生产运维仍待验收 ｜ updated: 2026-11-14

## 结论

仓库已经有面向校内 Linux 的全栈 Compose、独立 TLS 覆盖配置、SQLite 新路径备份/恢复工具，以及显式隔离的全栈验收 runner。当前方案默认建立新数据库卷和新合成账号，不导入旧库或运行数据。静态配置和工具具备继续推进的基础，但还没有证明固定目标镜像在当前环境可构建、完整服务可启动、真实证书可用，也没有异机恢复或校内生产运维证据，因此目前不能称为生产就绪。

本轮起点：`git status --short` 为空；分支 `codex/application-delivery`；HEAD `9f8283b0e9faa9c109d7f09779a8b42a2b4f9702`。本轮运行了只读计划 `py -3.12 scripts/verify-fullstack.py`，退出码 0：preflight 通过，模式为 `plan`，build、容器、HTTP 和恢复阶段均为 `not_run`，没有创建 QA 目录或 Docker 项目资源。Docker daemon 当前可用，版本 `29.2.1`。

## 本轮验证记录（2026-11-14）

- `py -3.12 scripts/verify-fullstack.py`：退出码 0，`mode=plan`，preflight 通过，其余阶段 `not_run`；没有创建 QA 目录或 Docker 资源。
- `py -3.12 scripts/verify-fullstack.py --run --timeout 600`：退出码 1。preflight、私有 QA 配置准备和 `compose config --quiet` 通过；build 因 Docker Desktop 没有 HTTPS proxy、无法直连 Docker Hub 获取 `python:3.12-slim` 元数据而失败。新卷初始化、容器启动、HTTP 与恢复阶段均为 `not_run`；本轮 project 的定向 cleanup 通过，卷前后均为空。目标全栈容器没有启动。
- `py -3.12 scripts/verify-nginx-transport.py --run --nginx-image nginx:alpine --probe-image python:3.11-slim-bookworm`：退出码 0。缓存 Nginx `1.31.1` 与合成 Python `3.11` 镜像上，`nginx -t`、健康代理、SPA 回退、gzip、SSE 分段到达、WebSocket 握手/首帧、QA CA TLS 校验、非 root/只读根/移除全部能力均通过；3 个合成容器与网络清理退出码均为 0。该探针不是固定目标 `nginx:1.30.6-alpine` 镜像验收，也不验证应用或正式证书。固定目标镜像和 `python:3.12-slim` 本机缓存均不存在，因此没有运行目标镜像 TLS 探针。
- 合成 WAL 备份演练：源 SQLite 写入并保持 WAL 连接打开时，调用备份 CLI 至新路径，再将备份恢复到另一个新路径。两条 CLI 均退出 0，快速检查 `ok`、1 张表、外键违规 0；恢复后合成行数为 1，项目现存数据库未触碰。
- 上述全栈与 TLS 验收均使用本轮生成的随机 QA 名称、合成服务/证书和 loopback 端口。忽略目录 `tmp/` 中保留本轮私有摘要、日志、合成证书和合成 SQLite 备份演练文件；未纳入 Git。仅登记 Docker Hub 连接失败摘要，不公开原始日志。
- GitHub Actions API 已核验：本轮文档提交触发的 [`Offline quality checks` run #43568912083](https://github.com/Muzee2025/health_new/actions/runs/43568912083) 完成成功，`backend` 与 `frontend` 两个 jobs 均 success；该分支的 `workflow_dispatch` run 查询为空，故 `fullstack-acceptance.yml` 没有本轮远端验收结果。GitHub Releases API 未返回公开 Release，拟用 tag `deliverables-20261104` 也未在远端找到。`gh` CLI 本机仍未认证（`gh run list`、`gh release list` 均退出码 4）。这些 CI 结果不代表目标容器、正式 TLS 或生产验收通过。

## 差距与实施顺序

| 优先级 | 差距 | 关闭条件 |
| --- | --- | --- |
| P0 | 固定目标镜像和 Compose 实际启动未通过。已有历史记录在 Docker Hub 元数据阶段失败；当前只读计划不包含 build。 | 在网络可达的隔离 Linux runner 上执行手动全栈验收，确认目标镜像构建、空卷初始化、readiness、合成登录/权限、备份恢复与定向清理全通过；保存脱敏摘要和准确的 Actions run 链接。 |
| P0 | 正式 TLS、DNS、证书权限和续期未验收。 | 使用校方实际域名和证书，在固定目标镜像上验证 `nginx -t`、443 访问、证书链/主机名、密钥读取权限及续期责任；不得以 QA 自签证书替代。真实证书与 DNS 未提供前仅能完成合成环境验证。 |
| P0 | 备份边界不完整。数据库备份工具不包含上传及生成文档卷；目前没有已确认的异机副本、保留/加密策略和定期恢复演练。 | 由校方数据责任人确认需保护的卷、加密/访问和保留要求；在全新隔离位置验证数据库与必要文件的备份、恢复和可用性。不得向现有业务库执行恢复。 |
| P1 | 日常运维闭环未定义为可交接程序：未见已验收的磁盘/卷容量、备份失败、服务不可用告警、日志访问/留存与事件响应流程。 | 明确值守责任人与校内流程，补充检查频率、告警处理、日志留存和恢复记录；用演练结果而非文档描述确认可用。 |
| P1 | Release 交付尚未完成。 | 用户/Lead确认 Release 附件范围和 tag 口径、获取 GitHub Release 凭据后，由 Lead 先复核远端状态，再按逐路径规则执行和校验附件大小/哈希/引用；本轮不做远端写入。 |
| P0（组织准入） | 商业/机构运行的实际责任人与环境信息未齐：校内域名/服务器、值守与隐私责任、容量目标、模型/专业服务策略和试点批准尚无本轮证据。 | 获得真实责任人和校内审批，并完成隐私、专业、模型、容量和应急流程评审。任何工程验收均不能代替这些批准。 |

## 建议推进

1. 先用现有隔离 runner 在 Linux 环境关闭 P0 目标镜像与全栈容器证据；GitHub run 状态在有只读访问权限后补记。
2. 再以合成证书和固定目标镜像关闭 TLS 配置问题；真实域名、证书和防火墙由校方提供后单独验收。
3. 与校方确认数据卷备份范围，再扩展或组合备份工具，做新路径、异机恢复演练并记录结果。
4. 完成值守、告警、日志与 Release 附件交接。
5. 最后由校方责任人决定是否进入受控试点/商业运行；本报告不构成生产放行。

## 安全边界

本轮未读取 `.env` 或任何现存项目数据库内容，未触碰现有业务服务/容器/卷、真实证书、DNS 或 Release；未运行旧 `backend/scripts/init_db.py`。全栈 runner 在目标镜像 build 阶段失败，未启动目标容器；TLS 探针只启动本轮 loopback 合成容器与网络，随后定向移除且无卷。另在忽略目录 `tmp/` 创建了全新合成 SQLite/WAL 源库、备份及恢复目标。默认 QA 计划只验证资源可用性，不读取或传递现有项目配置。不得用 plan 或缓存替代镜像探针结果。
