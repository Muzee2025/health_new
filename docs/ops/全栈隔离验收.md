# 全栈隔离验收

> owner: D / Lead整合 ｜ version: 1.1 ｜ status: 工具与合成契约通过；目标镜像构建受阻 ｜ updated: 2026-10-24

本说明记录可复跑的全栈 Docker/HTTP 隔离验收。执行者必须先检查命令计划和当前 Docker 状态；默认模式只做 preflight，不创建项目资源。实际运行仅由 Lead 在确认隔离环境后显式执行。

## 复跑方式

从仓库根目录运行：

```powershell
py -3.12 scripts/verify-fullstack.py --help
py -3.12 scripts/verify-fullstack.py
py -3.12 scripts/verify-fullstack.py --run
```

默认 HTTP 端口为 `4188`。如果被占用，可显式选新的空闲 loopback 端口：

```powershell
py -3.12 scripts/verify-fullstack.py --run --port 4189 --timeout 180
```

Runner 拒绝保留端口 `8000`、`5173`、`18080`、`18081`，并在运行前绑定 `127.0.0.1` 检查所选端口空闲。Compose 只绑定 `127.0.0.1:${HTTP_PORT}`。

## 隔离与执行顺序

每次运行生成 `healthnew-qa-<随机值>` project 名与仓库忽略目录 `tmp/healthnew-qa-<随机值>/`。拒绝重用现存输出路径、tmp 符号链接/junction 或已有同名 Compose project 的容器、网络、卷。新目录在 POSIX 使用 `0700`；Windows 使用仅当前用户的私有 ACL，无法建立 ACL 时停止并记录 setup 失败。仅在该目录写入 QA 签名、学生账号合成凭据、summary 和私有 Docker 子进程日志；不读取现有 `.env`、SQLite 文件、用户配置或业务响应来生成输出，也不设置 provider/RAG 凭据。Compose 子进程仅继承必要的系统路径与 Docker endpoint 变量，宿主 `COMPOSE_*`、`PUBLIC_ORIGIN`、`RUNTIME_ENV_FILE`、数据库与密钥变量不会传入。

执行顺序：Compose `config --quiet`、build、在新 database volume 里运行 `init-empty-database.py` 初始化 `health.db`、`up --wait`、HTTP 页面/API 检查、同容器 backup/restore 对照、只取安全字段的容器 inspect、最后仅对随机 project 执行 `down --remove-orphans`。默认保留命名卷和证据，不调用 volume 删除、prune 或全局停止命令。每个 Docker 子进程使用独立超时；失败时记为 failed，后续阶段保持 not_run，并仍尝试 project-scoped cleanup。

HTTP 验收只使用一次性 QA 学生账号：`/api/health/ready` schema 就绪、SPA 首页与本地 JavaScript 资源、注册后真实 `/api/login` 与 `/api/me` student role、教师公开注册拒绝、学生访问教师路由403、`POST /api/student/questions` 返回200且 `response_state=unassigned`、空白提问422。此流程不创建教师或师生分配，不发起模型/provider 请求。

备份阶段通过运行中的 QA backend 容器调用随镜像提供的 `scripts/backup-restore-database.py`。先将运行库备份到本轮新路径，再在 `questions` 表新增第二条带随机标记的合成问题，将备份恢复到另一个全新文件；容器内只读 SQLite 查询比较问题标记计数，并检查 27 表、6 触发器、`quick_check` 与外键计数。检查结果只输出计数和布尔结果，不输出业务文本。恢复目标不覆盖 `health.db`。

## 结果与边界

`tmp/healthnew-qa-*/summary.json` 列出各阶段 `passed`、`failed` 或 `not_run`，包括 cleanup 状态。失败或阻塞退出码为非零；setup 未完成、Compose 从未调用时 cleanup 标为 `not_needed`，不会尝试使用缺失的 QA env。cleanup 前后记录仅本 project 的命名卷；执行命令是 `docker compose -p <this-project> down --remove-orphans`，默认保留卷和证据。运行时 Docker 子进程的原始 stdout/stderr 保存在同目录私有 `logs/`，summary 只留安全字段和已脱敏错误摘要。不要把私有日志直接复制进版本库或公开报告。

验收仅覆盖隔离 Linux 容器镜像的本机 HTTP 路径与 SQLite 新卷恢复。它不证明公网部署、TLS、真实 provider、WebSocket/SSE、生产容量、跨主机恢复或生产数据迁移通过；没有在本轮访问真实账号、数据库、`.env` 或已登录浏览器标签。

## Nginx 独立传输检查

另提供 `scripts/verify-nginx-transport.py`。默认输出计划；显式 `--run` 才启动新随机QA项目的合成HTTP后端和Nginx。只使用本地已缓存镜像（`--pull never`），不构建或启动业务后端、不读取业务配置/数据。需要本机OpenSSL生成一天有效的合成证书；容器只读挂载该新证书目录。私有输出父目录限制访问，只有本次生成的测试key允许挂载给非root Nginx读取，此设置不能套用于正式私钥。

```powershell
py -3.12 scripts/verify-nginx-transport.py
py -3.12 scripts/verify-nginx-transport.py --run
```

默认要求已缓存`nginx:1.30.6-alpine`与`python:3.12-slim`，后者仅运行标准库合成HTTP服务。可用`--nginx-image`、`--probe-image`显式指定本机缓存；报告记录实际镜像ID和Nginx版本，不以替代镜像冒充目标镜像。`--openssl`可指定本机已有可执行文件，不安装软件或修改Docker代理。HTTP/TLS端口默认4189/4190且只绑定127.0.0.1，可通过`--http-port`、`--tls-port`更换空闲端口。脚本只停止/移除带本轮唯一label的容器和自己新建的网络，不挂载持久卷。

探针实际检查HTTP/TLS两组的`nginx -t`、合成健康代理、SPA回退、JS gzip、SSE首包早于延迟第二包、WebSocket 101/Accept/首帧、非root/只读根/移除全部能力。TLS客户端验证本次QA证书的IP SAN；这是本机代理协议检查，不是正式证书/DNS或应用鉴权验收。摘要保存为`tmp/healthnew-qa-transport-*/nginx-transport-summary.json`。
