## 2. 怎么判断"哪个是最新版"（口径）

时间戳会骗人，本盘点按四层证据判断，优先级从高到低：

1. **验收证据的 SHA256 绑定**：`docs/test/*.json`、`docs/ppt/**/README.md` 里登记的文件哈希是否等于当前文件哈希。
2. **docs 版本链与 status**：`docs/README.md`、`docs/ppt/six-chapters-20261029/README.md` 等写明的"当前/前版/供审阅"。
3. **文件内属性**：PPTX 页数（`ppt/slides/slide*.xml`）、DOCX 用 Word 只读打开得到的真实页数/表数/字数（`docProps/app.xml` 的 Pages 会过期，不可信）。
4. **修改时间**：仅作排序参考。

三个反例，正好说明为什么不能只看时间戳：

- `心域智链项目申报材料_图表增强审阅稿.docx` 的磁盘时间和 16 页版同为 10-27，但 Word 实开是 **32 页 / 19 表**，对得上 `docs/test/申报书科研图与数学分析验收.md` 的 S5 稿，是最新申报书；`docs/test/AI申报图表验收.md` 里写的"26 页"已经过期。
- `心域智链_18页逐页优化参考稿_20261101.pptx` 6.17 MB、时间最新，但 `docs/ppt/page-preview-20261101/README.md` 明写"**不作为最终样式获批或正式发布**"，不能拿它替代 R6 正式稿。
- `心域智链项目策划书_内容完善修订稿_20261029.docx` 是"最新"（40 页 / 20 表，与文档一致），**但当前文件哈希与验收记录不符**：验收登记 `61983966…ab7cc3`，实测 `f50a5d70…`。见 §8 第 1 条。

估算口径：当前 pack/工作树 ≈ 0.71；clone 体积按 pack 估算，只作量级参考。

### 方案 A 保守：只移出重复中间版本，历史不动

1. 7 个重复 ZIP + `心域智链.pdf` 复制到归档位置，核对 SHA256 后 `git rm --cached`（本地文件保留）。
2. 其中 4 个 ZIP（模拟库/合成问答/通用训练/旧提取包）被 7 处验收记录按哈希引用，需同步更新；另 3 个（申报书素材/矢量素材/方向矢量，共 1.94 MB）无引用，可直接移出跟踪。
3. `.gitignore` 增加 `deliverables/**/*.zip`，后续新版本不再入库。
4. 逐页预览等用户选定后再归档。

- 工作树：150.8 → 约 **134 MB**（只移 7 个 ZIP + 旧 PDF）；再归档预览对照图 15.35 MB 后约 **119 MB**。clone：**仍约 101 MB**（历史没动）。
- 风险：低；完全可逆（`git checkout` 恢复跟踪，本地文件不动）。
- 工作量：约 0.5 天。适合"先止血、不冒险"。

### 方案 B 推荐：归档仓 / Release + 一次性历史重写

1. `git clone --mirror` 全量备份到私有归档仓（或把 deliverables 二进制打成 GitHub Release 资产，tag `deliverables-20261112`）。
2. 主库只留"最新版 + 文本清单"（R6、18 页参考稿、32 页申报稿、16 页申报版、40 页策划书、37 页计划书、大纲、讲稿、模拟库 ZIP、训练 jsonl、xlsx、示意图），其余 `git rm --cached`。
3. `git filter-repo --path deliverables --invert-paths` 清历史（**Lead 决定并执行，本 Bot 不执行**）。
4. 更新 docs 里指向旧 commit SHA 的引用（门禁记录等），并按 AGENTS.md 登记归档原路径。

- 工作树：约 **84 MB**；clone：估 **60 MB 上下**（docs 39 MB 里位图占 32.9 MB，压缩有限）。
- 若再把模拟库 CSV（21.2 MB）单独移 Release，并把 `docs/` 位图（32.9 MB）归档、逐条改链接：工作树约 **30 MB**，clone 约 **18–22 MB**。
- 风险：中高——所有 commit SHA 变化、需要 force push、协作者要重 clone、docs 中 commit 引用失效；**文件内容 SHA256 不变，验收哈希仍有效**。

### 方案 C 激进：只留每类最新版

- 主库只留最新 PPT/文档/数据清单 + 代码 + docs 文本，历史版本与素材全部进归档仓/Release；docs 位图也移出并改链接。
- 工作树：约 **18–20 MB**；clone：估 **12–15 MB**。
- 风险：高——用户可能还要 8 页稿、旧讲稿、对照图；docs 断链需逐条改；可逆性差。
- 只有在用户明确"历史版本一律不要"时才建议。
