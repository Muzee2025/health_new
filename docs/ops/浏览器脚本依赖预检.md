# 浏览器脚本依赖预检

> owner: A ｜ version: 1.0 ｜ status: 已实施，依赖预检技术项通过 ｜ updated: 2026-11-13

9 个浏览器脚本统一使用 `scripts/optional-script-dependencies.mjs`。缺少可选包时，在创建输出目录、读取 QA 账号或执行构建之前退出，错误写入 stderr，退出码为 2。脚本不会安装包或下载浏览器。

## 检查入口

在仓库根目录执行，保留 `--check-deps`：

```powershell
node scripts/capture-attachment-ui.mjs --check-deps
node scripts/verify-interface-ai.mjs --check-deps
```

所有下表脚本都支持同一参数。成功退出 0，失败退出 2；stdout 输出一条 JSON，包含脚本名、`checkOnly`、`ok` 和逐包检查结果。stderr 只列包名、受限错误码和配置变量名，不回显配置值或原始错误栈。

检查入口会解析并加载包以检查必要的导出，不启动浏览器、不访问预览页面、不读取 QA 账号、不执行调用脚本的构建/截图/图像处理。包可以加载不代表浏览器已安装，不能据此认定页面验收通过。不要用 `import()` 导入这些顶层入口做调查。

## 依赖与解析顺序

| 脚本（位于 scripts/） | 必需可选包 |
| --- | --- |
| capture-attachment-ui.mjs | playwright |
| capture-ui-baseline.mjs | playwright、sharp |
| capture-w2-ui.mjs | playwright、sharp |
| check-chart-gallery.mjs | playwright、sharp |
| check-client-isolation.mjs | playwright |
| check-content-experience.mjs | playwright |
| check-frontend-loading.mjs | playwright |
| export-application-diagrams.mjs | playwright、sharp |
| verify-interface-ai.mjs | playwright |

优先使用 `PLAYWRIGHT_MODULE_PATH` / `SHARP_MODULE_PATH` 指定的现有包目录或入口文件；相对路径以启动命令的工作目录解析。未指定时沿用 Node 模块解析，包括项目本地安装及在启动 Node 前设置的 `NODE_PATH`。

`export-application-diagrams.mjs` 继续兼容旧 `CODEX_PLAYWRIGHT_PATH`，优先级低于 `PLAYWRIGHT_MODULE_PATH`。两处写死的用户缓存路径已移除。

显式路径错误时直接失败，不悄悄选择另一份安装；应修正或移除对应变量。包入口能解析、内部依赖不能加载时，JSON 的 `phase` 为 `load`；导出不符合所需接口时为 `exports/INVALID_EXPORTS`。

如已有其他位置的安装，可在当前 PowerShell 会话配置（替换示例路径）：

```powershell
$env:PLAYWRIGHT_MODULE_PATH = 'D:/existing-node-modules/playwright'
$env:SHARP_MODULE_PATH = 'D:/existing-node-modules/sharp'
node scripts/check-chart-gallery.mjs --check-deps
```

本次未将 playwright/sharp 加入工程依赖或更改锁文件。去掉 `--check-deps` 会执行各脚本原有主流程，可能重建输出或写入已登记图像，运行范围须沿用对应任务授权。
