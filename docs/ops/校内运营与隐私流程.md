# 校内运营与隐私流程

> owner: D / Lead整合 ｜ version: 0.2 ｜ status: 待校内责任人确认 ｜ updated: 2026-10-22

## 适用边界

本文是待校方确认的最小流程草案，不代表学校已经设立岗位、完成法律合规评估或批准试点。责任人、服务时段、联系人、升级时限、数据保存期限与删除依据均为待确认；没有提供的实际人员和电话不在此虚构。系统目前不应被描述为全天候心理危机服务或紧急救援渠道。

## 账号开通、变更和停用

教师账号应由校方指定的身份管理人员核验任职身份、审批用途并通过受控流程开通。教师离岗、权限变更或长期停用时，应及时冻结登录并复核其仍需保留的业务记录。具体审批人与操作人名单、核验方式和时限待校方填写。

公开注册只用于学生角色。教师只可访问已显式分配给自己的学生。可信师生关系由获授权操作员维护，不采信教师自行填写的advisor字段作为权限证据。当前现有命令行分配工具支持`list`、`grant`、`revoke`；具体命令参数以当前CLI `--help` 和代码为准，操作前核对学生/教师内部ID、审批依据与目标环境。执行后用`list`复核并将审批单号、操作人、时间、复核人记录在校方受控系统。不得建立“全体学生”分配或扩大管理员可见范围来绕过审批。

本轮提供`backend/scripts/manage-teacher-accounts.py`离线工具，新建教师、停用和重新启用均要求明确的SQLite副本、全新备份路径、操作员标识和审批原因。新建拒绝已存在的用户名，不能把既有学生提权；密码只从隐藏交互输入读取两次，不接受命令行密码参数。停用提升该账号的认证epoch并撤销其分配，已发JWT立即失效；重新启用不恢复旧JWT或原分配，需要重新登录及单独审批分配。历史账号没有状态行时视为epoch0；缺少账号状态schema则认证返回503，不绕过检查。

以下仅为操作模板：应先停止本项目写入并用隔离副本演练，换成批准的目标、操作人和审批单，不在未备份原库执行；每次使用不同的不存在备份文件。当前任务没有创建或停用任何真实账号。

```bash
python backend/scripts/manage-teacher-accounts.py \
  --database /校方批准的独立副本/health.db \
  --backup /校方私有备份/before-create.db \
  --operator "实际操作员" --reason "实际审批单号和用途" \
  create-teacher --username approved-teacher --name "经核验的姓名"

python backend/scripts/manage-teacher-accounts.py \
  --database /校方批准的独立副本/health.db \
  --backup /校方私有备份/before-disable.db \
  --operator "实际操作员" --reason "实际停用审批依据" \
  disable-teacher --username approved-teacher

python backend/scripts/manage-teacher-accounts.py \
  --database /校方批准的独立副本/health.db \
  --backup /校方私有备份/before-enable.db \
  --operator "实际操作员" --reason "实际恢复审批依据" \
  enable-teacher --username approved-teacher
```

账号动作保存在追加事件表中，SQLite触发器阻止普通UPDATE/DELETE，但不能防止数据库管理员直接改变schema；操作员标识由受控主机操作人填写，不能等同校级SSO认证。应用当前没有完整的管理员控制台。每次分配操作的完整业务审计、身份核验、审批与双人复核仍需校方流程补足。停用造成的留言、预约和跟进交接需由责任人另行审批，不自动把所有学生或内部任务转给其他教师。

## 求助、预警和跟进

求助与风险内容由校方明确的值班/个案责任人按书面分级规则受理。建议流程为：确认来源和时间 → 判断是否需紧急人工联络 → 记录客观事实与判断依据 → 指定跟进人和期限 → 复核是否完成 → 必要时按校方流程升级。系统中的自动提示仅供人工复核，不是诊断或临床判断。预警漏报、误报、无人接单时的替补责任人和升级时限均待校方确定。

人工联络渠道尚未接通。部署上线前需确认校内心理中心、辅导员/值班岗位、校医院及紧急服务的具体联络方式、服务时间、替补机制和触发标准，并在界面中清楚告知学生。不要将本系统的在线状态视为工作人员已收到消息。

个案查看遵循教师显式分配范围。导出前应核实请求人权限、导出字段、用途和接收方，采用校方批准的加密交付方式并记录审批。聚合统计不得反推出未分配学生或变相扩大查看权限。没有临床数据全局可见的管理员角色被本流程授予。

## 内容与社区审核

校方应指定内容审核主责与替补，制定社区发帖、图片/文档、举报、删除、申诉和高风险内容升级规则。审核员只访问完成审核所需的最小范围；涉及个人心理信息的内容转交个案责任人，不在公开社区讨论或用截图传播。当前系统不代表已经具备完整的内容治理、人工联络、审计记录或全天候值守能力。审核队列缺口和处理时限需在试点前确定。

## 隐私、留存与删除请求

校方数据负责人应为每类账户、问答、报告、上传文件、预约、日志、备份和模型请求确定目的、最小字段、访问范围、保存期限、删除/更正路径及备份过期规则，并告知学生。只收集服务所需资料；避免在工单、CI日志、普通群聊和截图中复制学生文本。

收到查阅、更正、导出或删除请求时，先由校方隐私/数据责任人核验请求主体和法律/业务依据，再批准执行。操作人应确认受影响的数据表、上传、日志、缓存与备份策略，记录处理结果并复核。当前没有自动删除全链路、完整审计或已批准的法定保存期限；不得自行承诺立即彻底删除或直接清理数据库记录。

## 事件与试点前置

发现错配师生、疑似越权访问、账号遗失、数据误发、备份介质丢失或服务中断时，停止相关访问或交付，保留必要的脱敏技术证据，并依校方安全事件流程通知指定负责人。联系人、报告渠道、响应时限、对学生告知方式及外部报告义务需由学校确认。

试点前至少由校方书面补齐：产品/数据责任人、教师身份审批人、分配操作人及复核人、求助与危机值班和替补、社区审核人、隐私请求承办人、事件联系人、保存/删除规则、人工联络信息、试点范围与退出机制。涉及预算、校外合作、伦理审查或申报的事项需依据真实批准文件另行填写。本文本身不表示这些条件已满足。
