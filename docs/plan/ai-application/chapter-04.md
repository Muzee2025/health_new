# 四、营销策略与服务实施

## （一）以校内问题验证作为进入起点

前章所述学校规模与政策方向说明了潜在服务场景，并不等于采购需求或可触达客户。本项目不以扩校、广告获客或预设转化率作为当前策略，而先验证高校心理服务中“测评之后如何说明、复核与衔接支持”的真实任务。重点关注青少年阶段常见的成长适应、情绪困扰、人际关系，以及高校学生面对学业、就业和生活变化时的压力体验；这些是访谈和服务流程需要核实的主题，不用来推断个体风险或诊断。

访谈须先取得学校业务部门对对象、方式和记录范围的批准。由校方指定协调人安排学生自愿表达、教师/心理服务人员流程访谈，以及管理、信息化和采购角色的制度核对；不自行招募真实学生，不收集可识别的心理经历。访谈提纲围绕现有流程、测评工具和授权、结果由谁说明、求助如何答复、未承接事项如何升级、信息可见范围、系统故障替代方案及采购/维护条件。记录采用去标识化任务摘要，经校方确认后形成需求清单；无法确认的内容标为待核实，不当成用户结论。

| 沟通对象 | 要核实的任务 | 交付证据 |
| --- | --- | --- |
| 学生代表（自愿、经批准） | 告知是否易懂、是否知道谁可见、如何求助/退出 | 去标识化问题摘要、告知理解问题清单 |
| 心理服务与学工业务人员 | 结果复核、人工答复、跟进及转介的责任和交接 | 流程图、角色/权限矩阵、未承接处置路径 |
| 校级业务负责人 | 服务目标、适用对象、例外和人工保障 | 经确认的需求范围、责任人与决策记录 |
| 信息化/安全与隐私管理 | 部署、身份权限、数据流、留存删除、恢复要求 | 数据清单、风险与整改项、环境验收条件 |
| 采购/财务及相关管理方 | 采购主体、交付边界、运维责任及成本核算要求 | 采购路径核实项、费用口径与未决事项 |

## （二）分阶段演示与责任分工

需求清单通过校方业务审阅后，先在隔离环境用合成数据演示：学生知情说明和测评后信息入口、经授权范围内的教师人工复核、求助答复与后续跟进。AI仅作为经批准的辅助信息支持，范围限于授权数据统计、已提交材料摘要和知识支持；展示前明确其输入、输出、人工核查和不适用事项。AI不作测评解释、诊断、风险裁定或自动处置。不得把演示、离线合成案例或已有本机技术交付描述为真实服务成效。

学校业务负责人决定任务范围并指定承接责任；心理专业人员审查工具来源、适用性、告知文本、知识内容和人工复核规则；信息化/安全及隐私管理人员核实环境、权限、数据处理、日志、留存和退出措施；采购/财务按校内流程确认采购主体、合同范围与全周期成本；项目团队提供合成演示、问题清单和工程证据，不代替上述审批与专业职责。若责任人、专业审核、数据依据、模型提供商及版本、处理与保存约定未确认，则只进行不接真实数据的原型迭代，不接真实模型、不开展学生验证。

## （三）小范围可用性验证的门槛与判定

只有校方书面批准、学生知情且自愿、数据最小化方案与访问权限获审、人工支持和退出渠道落实、隔离环境及恢复流程验收后，才由学校确定验证对象和周期。参与者可拒绝或退出，不因拒绝影响其获得既有服务；不作隐蔽监控，不将参与或测评结果用于排名、惩戒或强制处置。初中与高中不属于当前版本适用对象；如提出需求，须分别开展学段需求访谈，另审年龄适配工具、未成年人告知/监护安排、校方责任及危机承接条件，在完成独立审批前不纳入本验证。

验证前由校方确定任务脚本、观察窗口、记录者和阈值，并以任务级数据判断，而非以心理效果评价：任务完成率＝无协助完成指定步骤数/启动该步骤总数；完成耗时＝从任务开始至提交的有效时间，按任务类型报告中位数及范围；关键理解率＝能正确复述目的、可见范围、AI边界和退出方式的人数/完成理解核对人数；错误/求助率＝发生错误或需工作人员介入的任务数/启动任务总数；人工承接率＝按流程完成答复或明确转介的事项数/需人工承接事项数。另单列权限拒绝、数据事件、系统故障及未完成原因；各项分母、缺失值和观察范围一并披露，不预设目标数值或宣称改善心理健康。

出现任何未授权访问或数据泄露、学生无法自由退出、结果被误作诊断或自动处置、专业人员认为存在重大误导、人工支持无法承接、关键告知无法理解、系统故障导致数据丢失或退出机制失效时，立即暂停相关验证并按校方预案保护参与者、通知责任人、保全必要审计记录；由校方完成调查和整改复核后决定是否重启。结束后提交去标识化任务结果、负担与故障清单、整改记录及未决风险，由业务、专业、信息化/隐私和采购责任方共同评审。是否继续、采购或扩大范围由学校另行决定，当前不承诺客户、转化率、费用或试点结果。
