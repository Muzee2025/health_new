## 给申报书使用的准确简述

本项目代码已经包含学生对话入口、模型服务适配、基于应用内知识条目的可选检索，以及由统计规则生成的个人报告；部分路径可调用Qwen、智谱等外部模型。仓库代码只能说明这些调用路径存在，不能证明本机或试点环境当前已配置、已启用或效果已验证。现有风险标签、情绪分值和模型返回的“置信度”均不能当作经过校准的患病概率、诊断结果或训练效果。项目拟将AI定位为对经授权信息作摘要、解释和服务导航的辅助工具，由教师或专业人员核对线索并承担实际沟通与处置；模型版本、知识资料、提示参数、隐私边界和独立人工评测须在试点前固定并留证。

## 复现难度分层

| 层级 | 难度判断 | 能复现的内容 / 关键限制 |
| --- | --- | --- |
| 演示规则和业务流程 | 低至中 | 本地规则、固定提示、聊天/报告/审核页面可用合成账号和合成文本演示。须固定代码提交、依赖、输入和时间窗口；存在当前日期及数据库记录等动态输入时，截图和数值不保证完全相同。 |
| 知识检索与一个模型辅助摘要 | 中 | 在独立环境启用RAG、固定知识快照与嵌入模型，再调用一个文本模型摘要，可以复现端到端流程。主要变量是供应商可用性、精确模型版本/别名、系统提示和用户模板、temperature/top-p/token上限、区域服务、检索切块/Top-k、索引版本及失败回退。外部模型输出通常只能求近似一致，不能保证逐字复现。 |
| 稳定专业使用 | 高，且超出单次代码演示 | 除工程稳定性外，需要经心理专业人员审核的任务定义和边界、部署与数据治理、可追溯资料、未成年人/危机处置机制、人工响应能力、跨群体偏差与错误分析、持续监控及校内治理。合成测试、API可调用和界面完成都不足以证明可专业使用。 |

复验建议固定并登记：Git提交号与依赖锁文件；精确模型/供应商/区域及接口版本；提示模板哈希、system prompt、温度、采样参数、token上限；知识库导出/版本与embedding、切块/重排参数；固定脱敏合成样例、时间戳和模型响应保存策略；请求ID、每次成功/失败/超时、延迟和实际token数；人工评分量规、评审人角色及独立评分记录。对外部模型只能承诺相同输入与配置下的**流程/统计口径可复跑、生成文本近似复现**，不承诺逐字确定性。

需在材料中区分四种“复现”：

1. **工程可运行**：相同代码/依赖/隔离配置下接口和页面能按流程工作。
2. **统计结果复算**：固定输入数据、时间窗和算法后，确定性统计汇总可重新算出相同数值。
3. **生成结果近似复现**：外部生成模型受版本更新、采样和服务端变化影响，通常只能做到同配置下质量分布相近或语义接近。
4. **临床有效性**：必须依赖预先设计、专业审核并获得必要审批的研究/试点证据；不能由代码、接口或复验结果推出。

本盘点未读取 `.env`、数据库、日志或真实数据，未导入应用、执行服务或调用任何模型提供商；只根据指定源码、前端入口与已提交评测方案作静态判断。行号是当前工作树读取时的定位，后续代码变更后需重新定位。

## 主体章节可补充的事实边界

第一章“AI协助整理，专业人员负责回应”方向与现有系统定位相容，建议在该段后加入一段简洁的工程现状说明，清楚区分已有基础与拟实施能力：

> 现有代码已包含学生对话和报告入口、外部模型适配、可选知识检索、规则统计以及教师预警审核与跟进记录流程，可作为后续试点的工程基础。当前代码盘点不代表模型已在目标环境启用或经专业评测；各项风险分值为线索或规则输出，不是诊断概率。项目拟先以固定知识资料和单一模型辅助摘要开展受控验证，保留错误与超时记录，由专业人员按预先制定的量规独立复核，再决定是否扩展功能。

建议第一章配套明确：对话摘要仅用于辅助阅读；测评得分按对应量表/规则解释；RAG回答显示来源片段且资料有版本；模型故障或无依据时允许空结果并转人工；预警审核由指定校内人员负责。不要写成“AI自动诊断/精准预警/临床预测”“情绪识别准确率已提升”“多模态模型已完成融合”或将模型 `confidence` 当概率。

后续实施章节可新增一个小节说明单模型基线、知识版本冻结、统一提示模板与参数、12个合成场景先做工程检查、心理教师审核rubric、固定完整调用分母与独立评分、错误/超时/延迟/token统计、通过门槛由校方和专业负责人事前确认。现有评测方案未提供真实提供商输出或实际门槛，因此结果与工期/预算不得推算或预填。
