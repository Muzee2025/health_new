# 第二章 产品与服务

## 2.1 产品定位：让测评之后的支持接得上

“心域智链”面向高校心理健康教育与支持流程，定位为连接学生自助、测评记录、授权人员查看、答复与后续跟进的软件原型。产品价值不在于用一个聊天机器人替代校内服务，而在于把分散的测评结果、学生自述、趋势信息与人工服务入口组织成可解释、可追踪的协作链条：学生知道可以从哪里开始，授权教师在职责范围内掌握待处理事项，学校可据此审视服务流程是否顺畅。系统不提供医疗诊断、治疗结论或自动危机裁定；工具、说明与人工承接责任由学校确认。

产品由五个环节构成。第一，学生依学校选定的量表作答，系统保存答案、量表标识、计分规则版本与时间，并说明结果来源及适用边界。第二，服务端按既定规则进行计分、字段校验、缺失与异常检查，并将一段时间内的记录汇总为趋势或维度统计。统计只描述记录，不等同临床判断。第三，在启用并完成审批的辅助场景中，AI可依据经审核的知识资料与经授权、去标识化的必要字段，起草简明摘要、图表说明或通俗解释，帮助理解记录、信息缺口与支持入口。第四，授权教师或心理服务人员核对来源与措辞，决定是否采纳。第五，教师答复求助并记录跟进，学生查看答复。平台由此衔接信息整理与人工支持。

| 模块 | 输入 | 输出 | 状态 |
| --- | --- | --- | --- |
| 测评与记录 | 经学校确认的量表答案、计分规则及必要时间信息 | 分数、量表记录与结果说明 | 本地原型页面及既有接口；量表授权与正式适配待确认 |
| 统计与趋势 | 当前用户有权访问的测评记录、对话情绪标签等结构化信息 | 描述性维度汇总、趋势图表、数据质量提示 | 部分本地技术原型已实现；不是专业测评结论 |
| 知识检索与摘要 | 经审核知识片段、最少必要且获授权的去标识字段 | 带依据的摘要草稿、解释性文字 | RAG为可选模块；真实提供商和生成质量未经评测 |

## 2.2 AI如何与系统协同

AI是嵌入既有权限与记录流程的可选处理环节。推荐的目标链路为：用户完成测评或提出求助后，后端先以当前账号身份校验记录归属和角色权限；仅筛选任务所需字段，移除姓名、学号、联系方式等直接身份信息，并在获得适当告知、授权与校内批准后组装请求。对话原文默认不应无差别送往外部模型。随后系统依据批准的知识库检索有限片段，将问题、结构化指标、必要上下文和检索依据按模板提交给指定模型；返回内容经过长度、字段、枚举值、数值范围、引用来源及禁止性表述校验，保存为带生成时间、模型版本和依据的“待复核草稿”。授权人员查看原始依据并人工确认后，才可将适当文字呈现给学生或写入后续服务记录。去标识、授权或依据不合格时不生成。

流程一：**测评记录解释**。系统先按经确认的量表规则计分并检查题目完整性、规则版本和异常值；统计层生成分数与时间趋势。AI依据结构化结果和审核资料起草说明，区分事实与解释，并提示缺失和规则限制。教师复核后决定是否展示；校验失败或未确认时只显示基础计分和人工入口。

流程二：**求助摘要与跟进**。学生提交的文字首先按现有角色和记录权限进入求助流程；如未来启用摘要功能，应先提取最少必要内容、剥离身份信息，再检索经批准的支持知识，为教师生成简短摘要及待确认问题。教师核对原求助并撰写答复，系统记录答复与跟进状态。AI不得代替教师给出专业结论或裁定危机等级，也不得触发处分、转介、通知家长等行动。

## 2.3 现有基础、可选能力与建设计划

仓库已具备本地技术原型：`backend/app/routers/advanced_chat.py`包含对话情绪标签、情绪趋势计算及失败时回落默认值的路径；`backend/app/services/dialogue_analysis_service.py`构建结构化报告；`backend/app/routers/report_v1.py`提供本人报告读取、分析任务与快速本地结果路径；`backend/app/routers/assistant_v1.py`提供基于已有报告或测评记录的维度数据；`backend/app/routers/teacher.py`按教师角色及明确分配关系限制学生问题、答复和跟进。前端`src/views/student/Test.vue`提供测评作答和结果界面，`src/views/student/Dashboard.vue`读取趋势与图表，`src/views/student/Report.vue`呈现报告，`src/views/student/Questions.vue`和教师端页面衔接求助与答复。代码存在不代表学校部署、量表适用性或AI准确性获认证。

检索增强生成由`backend/app/services/rag_service.py`实现为可选组件：默认关闭，只有显式启用、配置存储并允许初始化嵌入模型后才尝试工作；查询失败返回空结果，知识记录仍以数据库为权威来源。`backend/app/routers/llm_gateway.py`当前以本地回退函数生成文本或结构化回退结果，不是已接通并验证的外部大模型。报告服务另有外部LLM候选配置与超时/本地快速结果路径，属于可配置能力；真实提供商、模型版本、数据传输与保存策略、输出质量和成本均未经评测。前端出现的模型名称、AI分析按钮或演示标签不能单独作为实际模型调用证据。

因此，AI能力分三类：一是**已实现本地技术原型**，包括结构化记录、规则/本地分析、趋势展示、本人报告和受分配范围约束的人工服务流程；二是**可选但未经真实提供商评测的模块**，包括RAG索引和外部模型配置，默认状态与运行条件受配置控制；三是**拟新增AI分析模块**，目标是将统计质量检查、经审核知识检索、结构化生成、来源展示及人工复核整合为明确接口和可追踪任务。新增模块须先确认用途、字段、授权、模型及审核责任，再以隔离合成案例评估一致性、遗漏、越界、失败、延迟和成本；离线12个合成案例只用于工程演练，不构成临床验证或模型有效性证据。当前门禁记录显示后端135项通过、3项条件跳过及5项WinError10013环境错误；最新真实UI因Vite代理连接EACCES未通过完整集成。上述工程结果支持继续完善原型，不应表述为系统整体集成或AI专业评测已通过。

## 2.4 可靠性与服务边界

AI步骤可停用、可降级、可追溯。检索不可用、模型超时、输出格式不合格、授权或去标识检查失败时，任务标记为未生成/待处理，保留可读错误状态；系统展示已有结构化事实、人工联系入口及必要的重试方式，不能用旧结果伪装为本次新分析。学校可关闭外部模型或RAG，回到人工查看、答复与跟进流程。生成内容标注为辅助草稿，记录请求、模型/提示版本、检索来源、校验及人工处理状态；日志按最小化原则留存。

配套交付包括来源登记、权限矩阵、AI数据流、隔离评测、故障退回方案与培训材料。学校确定采用方式、复核人员、留存与紧急求助承接机制。当前首要产品对象为高校流程验证；中学需另行完成适龄工具、未成年人告知与保护、校方审批和危机承接评估，现阶段不宣称已有中学版本或真实试点。通过把机器限定在整理与表达，把专业判断留给有授权的人员，项目可在稳健边界内逐步验证AI对服务效率和信息可读性的实际价值。
