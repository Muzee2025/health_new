# 心域智链项目补全与改进方案

> owner: A / Lead ｜ version: 1.0 ｜ status: 方案已编制，工程实施待逐项推进 ｜ updated: 2026-10-31

本方案依据当前工作树、进度看板、门禁记录及2026-10-31新一轮隔离验证制定。目标是把已有学生端、教师端和求助工作流推进到**结果可信、数据可追溯、服务有人承接、部署可复验**的受控试点版本。本轮交付方案、任务清单和验证记录；下述改进尚未实施，真实施测、模型效果和生产准入尚未获证。

## 2. 实施范围与版本目标

先完成一个受控版本：学生完成已登记工具的作答，服务器校验并计分，报告可追溯到本次作答，学生可主动求助，分配教师可以审核和跟进，故障与降级状态可见，备份能够在新环境恢复。

工程优先按成年高校场景设计；实际目标人群仍须由负责人确认。未成年人作为另一个准入分支，补齐适龄版本、告知及人工服务条件后再进入，不能复用成人阈值。此处是排期假设，不是已经选定问卷或批准试点。

近期暂缓学校级全局管理台、新增量表数量、多模态识别、自研诊断或预测模型及数据库引擎迁移。当前求助schema校验明确限定SQLite，改成其他数据库需要另列兼容任务，不能作为“优化配置”顺手切换。

P0表示真实答卷/受控试点前必须解决，P1表示形成可维护版本所需，P2表示后续增强。未有证据的功能默认不在正式环境开启；演示环境使用合成题与合成账号，并明确标识。

| 报告可能高估数据依据 | [报告生成](../../backend/app/routers/student.py#L499)有未限定类别的latest_test；部分聚合已限定SDS/SAS；analysis_basis在调用RAG前固定加入知识检索说明 | 逐路径核对，趣味结果不得成为心理风险依据；无实际命中不显示“已检索”。空数据、规则回退与模型摘要分别标状态，不把低分写成已排除问题 |

## 4. 数据与接口设计

以下均为拟议结构，需要接口和迁移评审后实施，不是现有数据库字段清单。

| 拟议对象 | 最小内容 | 核心约束 |
| --- | --- | --- |
| 工具登记/题本快照 | instrument_id、category、form_version、language、适用人群、来源/权利证据、scoring_version、interpretation_version、题本hash、发布状态 | 精确绑定被批准版本；题目与规则快照不可原地改写；趣味工具不具备风险统计资格 |
| 作答与计分记录 | assessment_id、工具/语言/规则版本、必要的原始选项、提交状态、服务器分数、数据时间、notice_version及适用的告知/同意凭据关联 | 提交原始选项后服务器反向计分；不信任前端已反转的分值；缺项按手册处理；历史unknown不可与新版本默认混算 |
| 解释运行记录 | run_id、assessment_id或报告快照ID、输入hash、事实摘要、prompt_version、knowledge_snapshot、真实model_id、fallback、状态、时间 | 生成文本不能改分数；重试与迟到响应绑定同一输入；没有供应商元数据就记unknown，不填静态假值 |
| 知识条目与检索引用 | document_id、来源/权利、修订版本、审核/发布状态、片段ID、索引版本、命中引用 | SQL作为权威；编辑缩短/撤回后旧片段不得继续检索；未审核内容不进入正式索引 |
| 服务配置与处理事件 | 已有分配/事件基础上补服务时段、角色责任、受理/处理状态及必要期限 | 不自动分配真实学生；没有服务承接时明确不可用；新增字段不得放宽教师可见范围 |

提交接口建议演进为显式版本化契约：`instrument_id + form_version + answers + notice_version + submission_id`。`submission_id`用于同一次提交重试去重；`assessment_id`用于结果和AI关联。未知版本、重复/额外题、非预期选项、布尔代整数、过期题本及越权ID均有明确失败结果。是否保留旧路由由调用方核查决定，不静默改变旧客户端语义。

数据库按“全新QA库验证 → 源库只读备份到新副本 → 新副本升级/校验 → 另行安排服务切换”推进。迁移应有版本、schema对照、quick_check、外键检查、差异说明与新路径回退演练。旧库的已知外键异常单独登记，不删行掩盖。新增约束不能因旧行版本未知而伪造补值。
