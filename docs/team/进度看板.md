## 当前：阶段 2 格式化口径（2026-11-12）

格式化范围以 `package.json` 的 `format:check` 为准，即 `src/**/*.{js,ts,vue,css}`、`scripts/**/*.mjs`、`public/sw.js`、`vite.config.js`。`prettier .` 全仓库口径会多出 11 个文件（两个 workflow、`AGENTS.md`、`package.json`、`deploy/` 两个 yml、三个根文档、`dashboard/index.html`、`prompts/`），**这些不格式化**：它们不在任何检查口径内，改动只会污染 CI 配置与依赖清单的 diff。

**每批格式化后必须跑 `npm run assets:check`。** 语义校验只比对 `<script>` 块，模板改动它查不出来；`assets:check` 是唯一能兜住模板的检查。`e65e1dc` 就是靠它发现的。

`scripts/check-design-sources.mjs` 的 el-icon 检查已改为允许开闭标签跨行。原正则 `</el-?icon>` 要求 `>` 紧跟，Prettier 把 `>` 移到下一行后匹配不到闭合标签，icon body 会吞到下一个闭合标签，把 `<span>` 误判为未注册图标组件——表现为 `assets:check` 由 PASSED 变 FAILED。

`src/services/reportCache.ts` 是纯行尾文件（`i/lf w/crlf`）。`core.autocrlf=true` 来自系统级 gitconfig（仓库根无 `.gitattributes`），所以它在 Windows 上必然被 Prettier 判为不合格，Linux 上不会。这属于本机环境差异，**不要为它单独提交**。

**`format:check` 在 Windows 上的剩余报错全部是行尾假警报。** `测试` 的 `scripts/` 落地后，`format:check` 仍报 64 个文件；我把 HEAD blob 逐个用 `prettier.resolveConfig` + `prettier.format` 复核，**62 个 blob 本身就是合格的 LF 内容，只有 `Report.vue` 和 `AdvancedAiChat.vue` 真需要格式化**。这 64 个文件在 git 里零改动（`git diff --numstat` 为空），把工作区临时改回 LF 再 `git checkout` 还原后，状态回到 20 个待提交、无残留。判断标准是 **HEAD blob 是否合格，不是工作区 `prettier --check` 是否通过**——后者在 Windows 上永远报错。
