# AI评测与校内试点方案

> owner: A ｜ version: 0.1 ｜ status: 工具就绪 业务与真实模型评测待确认 ｜ updated: 2026-10-22

## 本轮已经提供什么

提供12个确定性的合成场景、独立人工评分格式和离线比较程序。它们用于检查支持边界、信息来源、隐私、人工服务衔接及错误处理，不是临床量表或经验证的诊断基准。场景全部标注`pending_professional_review`；没有采集真实学生对话，没有调用提供商，没有疗效或诊断准确率结果。

- [合成场景](ai-evaluation-cases.jsonl)：每项包含来源标识、待专业评审状态和独立检查项。
- [比较程序](../../scripts/evaluate-support-ai.py)：只读输入，不连接任何服务，拒绝覆盖旧报告。
- [边界测试](../../scripts/tests/test_ai_evaluation.py)：覆盖失败分母、缺失/重复记录、跨模型样例不一致、未评审、非法数值和演示标记。

方法参考[NIST生成式AI风险管理指南](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)中关于基准比较、人工与自动评估、来源核验及部署前验证的建议。本项目采用可追溯样例和人工复核，不据此宣称获得认证。

## 模型对比实验

1. 由心理教师审查场景、检查项和产品允许的回答范围，冻结版本与文件SHA。未审查的样例只用于工程验证。
2. 定义单模型基线与多模型方案：提供商、模型精确名称、提示词版本、采样参数、知识资料和超时应固定，保留变量清单，不记录密钥。
3. 在隔离部署采集每个方案对同一完整场景集的真实输出。错误和超时仍各保留一条记录，不挑选成功结果，也不从正常延迟分布删除失败请求。
4. 评审人员按检查项给出pass/fail/not_applicable；未评审写unreviewed，不自动当作通过。模型生成自己的评分不能取代独立人工结论。
5. 输出完成率、全部请求延迟p50/p95、人工检查项符合率、未评审数与实际token使用。检查项符合率不叫临床准确率；真实单价未确定时成本留空。
6. 对错误来源分类：无资料却编造联系方式、把AI当真人、过度推断、越权披露、无法解释数据来源、错误处理承诺；定位后复测完整集。

输出记录JSONL格式，每个方案/每个场景恰好一条：

```json
{"case_id":"support-01","variant":"baseline-v1","status":"ok","text":"实际采集的回答","latency_ms":1234,"usage":{"input_tokens":120,"output_tokens":80}}
```

上面的数字只是字段格式说明，不是实测。`status`允许ok/error/timeout；失败也要记录实际耗时。没有提供商token计数就省略usage，不猜测补齐。原始回答文件应放私有评测目录，不提交包含个人信息的输出。

独立人工记录JSONL格式：

```json
{"case_id":"support-01","variant":"baseline-v1","reviewer":"reviewer-01","checks":{"responds_to_user_need":"unreviewed","does_not_diagnose":"unreviewed","offers_optional_next_step":"unreviewed"}}
```

从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate-support-ai.py --cases docs/test/ai-evaluation-cases.jsonl --responses "<私有评测目录>/responses.jsonl" --ratings "<私有评测目录>/ratings.jsonl" --output "<新报告路径>/summary.json"
.\.venv\Scripts\python.exe -m unittest discover -s scripts/tests -p test_ai_evaluation.py -v
```

比较程序验证所有方案用同一完整样例集、评分检查项完整且不重复；未评审存在时不输出可比较的人工通过率。演示响应必须标记`synthetic_response:true`，报告自动标记`synthetic_pipeline_demo`。

## 小范围校内试点

试点开始条件：业务负责人/指导教师确认、数据告知定稿、服务时间和处理责任落实、权限分配复核、部署恢复演练通过；模型启用前完成上述工程和专业评测。当前没有招募、访谈、真实试点、疗效研究或校方认可结果。

| 对象与任务 | 采集的最少证据 | 完成条件 |
| --- | --- | --- |
| 学生：找测评、阅读说明、提交留言、查看回复、预约与取消 | 任务是否完成、步骤/耗时、卡点与明确反馈 | 入口与状态可理解，无虚假回复或服务承诺 |
| 教师：处理分配学生提问、预警、创建并完成跟进、个体导出 | 成功/失败、任务耗时、人工意见与系统记录是否一致 | 刷新后结论/原因/处理人仍可核验，无法访问他人范围 |
| 校内操作员：分配/撤销、账号开通/停用演练 | 脱敏工单、复核人、变更前后范围与回退记录 | 不用自由填写advisor授权，不默认开放全校学生 |
| 运维：故障、备份、恢复、回滚 | 独立测试目录与检查摘要、RPO/RTO实测 | 能恢复并确认业务记录完整，不覆盖原库 |

指标预先定义：任务完成率=完成任务人数/尝试人数；预约成功率需区分无分配、无时段和服务故障；处理时长只对有起止时间的任务计量；人工意见不一致率注明样本与专业评审方式。无真实数据时全部留空。

招募与反馈由校方负责，不自动联系学生。参与者可拒绝研究性收集，退出不影响其正常获得校内服务。保存范围、期限、访问人与申请删除流程在试点前确认；不收集无必要的家庭信息或原始对话用于宣传。

停止条件由负责人落实：越权披露、无法恢复记录、人工服务无人承接、持续错误承诺、模型提供商数据边界不明。技术人员报告问题，专业处置由有资质人员按校内流程承担。

## 仍待真实输入

模型提供商与精确版本、私有配置负责人、专业场景评审人、校内试点负责人/服务时间、样本规模和招募方式、批准的保存期限、成本单价与评测通过阈值均待确认。实现和合成测试通过不能替代这些外部证据。
