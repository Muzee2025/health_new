# W2 安全独立复核

> owner: Luna ｜ version: 0.4 ｜ status: 独立复核完成；全套通过 ｜ updated: 2026-10-22

## 范围与数据边界

本记录对应 W2-QA-SEC。复核对象为当前冻结的认证、上传校验、认证路由、教师路由、报告诊断、WebSocket 与 CORS 行为；另覆盖 Lead 新增的文章阅读计数和 ASGI 上传体积限制。测试只使用本用例建立的合成账号/文章、临时 SQLite、虚假 JWT 签名密钥与 runner 的临时工作目录。未读取 `.env` 或真实数据库，未连接 8000、外网或模型提供商。

测试文件为 `backend/tests/test_w2_security.py` 与 `backend/tests/test_student_assignments.py`。HTTP 测试使用 `tmp_path` 创建独立 SQLite schema，并以依赖覆盖将请求送入该库；认证 token 使用每个测试 fixture 临时设置的虚假密钥。文件上传只生成合成 PNG/PDF/DOCX 字节并由 runner 的临时工作目录承接。文章计数用新建合成文章，并核实数据库最终值。迁移和运维 CLI 测试另建临时 SQLite 文件，不从应用配置发现数据库。

## 检查内容与结果

- 严格 v2 JWT：伪造签名、过期、缺少版本/类型的 legacy token、非规范或非字符串主体、错误算法、错误 audience 均被拒绝。
- 身份一致性：纯数字用户名仍按用户 ID 认证；HTTP `/api/me` 与 WebSocket 子协议登录得到相同合成身份。`X-User-Id` 和 WS URL query token 均不能提供身份。
- 登录与注册：教师公开注册和弱密码被拒绝；现存 bcrypt 密码 hash 可登录；连续失败触发 429 与 `Retry-After`。
- 匿名和教师边界：会话、教师端 dashboard、报告诊断等需认证；学生不能进入教师预约、干预和教师资料接口；教师不能修改另一教师资料、查看或更新另一教师预约；干预列表按当前教师隔离。
- 报告诊断：响应只返回当前用户的安全作业字段，不泄漏测试注入的密钥/他人标记字段，DB 状态来自隔离 SQLite。
- 上传与下载：伪造 PNG/PDF 魔数拒绝；合成 PNG、PDF、非宏 DOCX 可上传；学生身份可下载受保护文件，未登录下载失败；静态目录不暴露文章文档，路径穿越文件名返回 404。单文件 5 MiB 边界超限拒绝。
- ASGI 入口：针对三个上传路由的无 `Content-Length` 分块请求，6 MiB 总请求体上限均在路由解析前返回 413。
- CORS：runner 配置的 `http://127.0.0.1:5173` 预检通过；未配置 Origin 预检返回 400 且不带 `Access-Control-Allow-Origin`。
- 文章阅读：相同合成 viewer 在去重窗内第二次请求不增加计数，新 viewer 再计一次；最终 SQLite 计数从 100 增至 102。
- 明确分配 ACL：两教师、两学生与未分配教师构成独立样本；学生教师列表的 `can_book` 与预约入口遵循分配。教师学生列表/详情、预约、危机列表与处理、干预、指标聚合、审核清单和 DOCX 导出仅包含分配范围；教师创建学生会建立其分配关系。
- WebSocket 通知：以真实 `ConnectionManager.broadcast_to_teachers` 和合成连接对象验证，只有学生所属教师收到通知，另一教师和未分配教师没有消息。
- 离线运维：SQLite schema upgrade 幂等，含分配记录时 downgrade 拒绝并保留表；grant/revoke 幂等，错误角色 ID 拒绝。所有 CLI 操作显式指向临时 SQLite 文件。
- 数据库初始化边界：独立子进程在显式临时 SQLite URL 下导入 `app.main`，导入期间封锁 Python socket/DNS，检查既不连接也不创建指定数据库。初始化 CLI 在临时目录创建新 SQLite schema；对既有空文件和既有 schema 均拒绝，前后 SHA-256 一致且内容可读。

## 实际验证

ACL 与数据初始化独立用例运行命令：

```powershell
.\.venv\Scripts\python.exe scripts/run-backend-baseline.py backend/tests/test_student_assignments.py
```

结果：退出码 0；7 passed，14 warnings，11.27 秒。runner 回显数据库和文件使用临时目录、dotenv/RAG 关闭、Python socket/DNS 默认阻断。命令没有启动应用服务器或连接本机服务。当前检查只验证明示断言的测试路径。

最终全套 runner 命令为 `.\.venv\Scripts\python.exe scripts/run-backend-baseline.py`，退出码 0：70 passed，24 warnings，46.25 秒。runner 用 `--disable-warnings` 隐藏了逐条 warning 分类，因此本次结果只能准确记录总数，无法从输出核实各 warning 来源。此前一次新依赖验证曾因旧测试仍访问 FastAPI `_IncludedRouter.path` 而失败；测试 owner 改用 OpenAPI/HTTP/WebSocket 公共契约后，本次全套通过。

runner 为支持 Windows asyncio `socketpair()`，仅在当前线程同步执行标准库 `socket.socketpair()` 期间允许到 `127.0.0.1`/`::1` 的 loopback connect；DNS 仍拒绝。这个例外没有按端口或具体 socketpair endpoint 再细分，代码层许可范围因此比“仅允许唤醒 socket 的那个 ephemeral peer”宽。正常 Python socketpair 用于创建自身临时唤醒通道；审阅中没有发现该路径会连接项目 8000 端口。该 runner 是测试误连防护，不是 OS 级或子进程/原生扩展网络沙箱。

## 待追加复核与边界

ACL 测试检查显式分配关系过滤了上述选定端点的列表、详情、处理和导出数据；它不代表所有教师敏感端点都已穷尽。未覆盖的未来路由仍需沿用相同分配边界并添加针对性测试。测试不以自由填写的 `advisor` 字符串推断授权。全套 suite 的唯一失败需由原测试 owner 决定：若 mock 记录应保持不可见，应调整旧断言；若产品契约仍需展示 mock 项，则应先在访问控制规则中定义其所属关系。

本轮未检查并未覆盖：生产代理/多进程下限流共享性、真实对象存储/Windows ACL、恶意 ZIP fuzz、反向代理的超大分块传输和部署端 CORS 覆盖。测试通过只说明列出的本地边界在当前冻结代码及此隔离入口下符合断言，不构成上线安全认证。
