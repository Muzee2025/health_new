## 后端第三批边界

### 1. Crisis 与 follow-up 路由必须分段插入

拆分前基线 `teacher.py` 的 `router` 前缀是 `/api/teacher`、标签是 `Teacher`（第 47 行）。方案列入 `teacher_crisis.py` 的 7 条路由由三条 crisis 和四条 follow-up 组成；它们被两条保留在学生管理组的 questions 路由隔开，原始顺序为：

1. `GET /crisis/pending`（第 203 行）
2. `POST /crisis/review`（第 247 行）
3. `GET /crisis/{warning_id}/reviews`（第 305 行）
4. `GET /questions`（第 338 行）
5. `POST /questions/{question_id}/answer`（第 417 行）
6. `GET /follow-ups`（第 461 行）
7. `POST /follow-ups`（第 477 行）
8. `POST /follow-ups/{task_id}/complete`（第 550 行）
9. `POST /follow-ups/{task_id}/cancel`（第 558 行）

若把 7 条 crisis/follow-up 路由一次性插入 crisis 原位置，会把 follow-up 提前到 questions 之前，改变路由注册顺序。`985efc6` 当前采用两个 router 并在 questions 路由前后分别展平，静态位置与原序相符。

`teacher_media.py` 的 4 条路径在原文件相邻后续位置：`POST /upload`（565）、`GET /documents/{filename}`（602）、`POST /avatar`（616）、`POST /avatar/from-picture`（645）。主 router 当前以 crisis、follow-up、media 顺序展平；还需用完整快照确认拆分后 100 个 `path+method` 对及顺序完全一致。

### 2. 两个共享 helper 与 articles 顺序

拆分方案第 61 行已正确列出两个跨组 helper：

- `check_teacher_role`（拆分前基线 `teacher.py:105`），被多个路由组调用；
- `_build_avatar_url`（拆分前基线 `teacher.py:111`），由媒体侧头像 upsert（原调用点 175）和 dashboard appointment/profile 路由（原调用点 881、1333）共同使用。

`985efc6` 当前将两者从 `teacher_shared.py` 导入主 router；media 模块也从共享层导入它们。若旧测试或调用方依赖 `teacher.py` 名称，应保留兼容导出。此前认为方案只列一个 helper 的提醒已过时，当前方案文档已正确。

本批不移动 articles 路由。拆分前基线第 1207、1227 行分别是 `GET /articles/page` 与 `GET /articles/{article_id}`；最终应通过完整快照确认字面路径仍先于参数路径。

## 前端 C2 测试先行

方案 `docs/design/前端大文件拆分方案.md:170` 要求先覆盖 404 自愈、登录身份切换、匿名边界、服务端失败本地回退、IndexedDB 持久化，再迁移会话索引/同步、切换删除、草稿与滚动状态。

截至复核快照可见的测试草稿：

- `useChatSessions.test.js`：4 个 contract 案例，覆盖 404 后切 survivor、本地消息 fallback、token 改变后阻止旧身份读取、草稿/滚动持久化与匿名模式跳过草稿保存。
- `AdvancedAiChat.sessions.test.js`：4 个页面级案例，覆盖 404 后切 survivor、本地缓存 fallback、匿名切换清空内容且不保存 UI 状态/不请求会话 API、token A→B 后阻止旧 session 本地读取。
- `chatIndexedDb.test.ts`：用自定义 `MemoryIndexedDB` 执行真实 `createChatStorage` adapter，覆盖 conversation/message/ui_state 跨同身份 storage 实例读回与另一身份隔离。

现有用例方向有效，需补足或明确缩小以下范围后再把 C2 标为通过：

1. **404 清理**：给失效会话预置 message 与 ui_state，断言 conversation/message/ui_state 都被清理；另覆盖没有 survivor 时创建新会话。
2. **身份切换晚响应**：页面级发起 A 身份的 deferred API 请求，切到 B 后再返回；断言 A 的迟到响应不能覆盖 B 的列表/消息或写入 B 缓存。现有 `privateChatSession.test.ts` 的 late-response 单测仅证明 service guard 拒绝结果，不等价于页面状态断言。
3. **匿名写入**：当前页面测试验证切换时清空历史/草稿且不保存 UI 状态、不请求会话 API；composable 用例验证匿名不保存草稿。建议再断言匿名路径不调用 `upsertConversation`/`putMessage`。
4. **IndexedDB 删除语义**：`chatIndexedDb.test.ts` 的自定义内存 fake 验证 adapter 跨实例读回与身份隔离，但未覆盖 `deleteConversationLocal` 的 message/ui_state 级联删除、游标行为或浏览器 transaction 语义。可补 adapter 级级联断言；若验收要求浏览器 IndexedDB 语义，应另用 IndexedDB fake 或隔离浏览器验证，并区分测试范围。
5. **删除会话路径**：composable contract suite 当前无 `deleteSession` 远端失败保留本地、远端成功后清理/切换的案例。
6. **失败回退**：当前 network failure 案例保留本地消息的断言有效；可保留明确 `503` 与断网中的至少一种边界，并断言本地数据不被误删。

页面现在已导入 composable，但本复核没有页面接入前目标测试的命令、退出码及通过数；不能据此认定测试先行门槛通过。前端如已先跑并通过，应补齐可核验记录；否则应先完成目标测试与结果确认，再继续迁移。
