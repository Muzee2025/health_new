## 代码复核

- `backend/app/services/article_catalog.py` 仅投影列表摘要字段，不选择文章正文；查询支持标题/摘要/来源文本搜索，LIKE 特殊字符按字面转义，分类按首尾空白归一，阅读量将空值和负值归零，并以创建时间及 id 稳定排序。页码夹紧到有效范围，每页上限由路由约束为 50。
- 学生与教师分别新增 `/api/student/articles/page`、`/api/teacher/articles/page`。教师端执行原角色检查；原有全量文章列表与详情路由保持可用，文章详情和阅读量行为仍走原接口。
- `ArticleSummary` / `ArticlePage` 响应模型不含 `content`。学生与教师页面共享 `useArticleCatalog`，支持搜索 debounce、筛选/排序回第一页、过期响应忽略、无效分类复位、服务器页数夹紧、错误重试及卸载取消请求。两页均接入分页接口。
- 启动器显式要求独立配置与对应目录中的 `health.db`，清理继承环境变量，支持将工作目录切换到部署目录；`--block-outbound` 使用 Python audit hook 阻止 DNS/socket 连接。该 hook 不是 OS 级网络沙箱，操作指南已明确这一点。
- 计数器修复已冻结复核：SQLite 写锁有界重试，失败返回 503 并释放本次去重 token；写入与读取计数处于同一事务，提交后仅更新进程内缓存。新增 SQL 事件断言检查提交后没有数据库 I/O。当前未发现分页或计数器代码的确定性阻断缺陷。

## 门禁结论

文章摘要分页 API、启动隔离专项测试及 composable 测试由复核者亲跑通过；Lead较早一轮合成 UI、真实预览和页面回归证据通过审阅。最新真实 UI 两视口均因 Node/Vite 代理 `EACCES` 失败；readiness 200 未能替代端到端连通性。计数器新增专项测试通过，但整组在该 Windows 隔离执行环境出现可重现的 portal 启动失败，与执行者的一次整组通过结果不一致。最新完整后端集成也有 5 个同类环境错误。隔离启动器验证了日志相对路径所在工作目录，但没有实际日志写入证据。因此本轮完整 QA/后端集成门禁**未通过/阻塞**，不能仅凭局部定向通过关闭全套门禁。

此记录不批准生产部署。Linux/TLS 容器、生产配置与恢复演练、医学/专业内容审查、校内隐私与业务审批仍需各自完成；本地合成数据和浏览器通过不替代这些批准。
