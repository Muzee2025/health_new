## 本轮范围

用户要求完成此前提出的补充建议，并指定子代理使用Luna。起点为`a396b72`，工作分支`codex/support-delivery`；开工工作树干净。后端、前端、部署和申报工件分别由唯一owner执行，Lead负责集成、离线AI评测、团队记录和Git。附件中的要求用于对齐申报格式，其他应用中的对话不增加授权。

| 交付 | 实现与验收范围 | 不包含的结论 |
| --- | --- | --- |
| 学生留言与教师回复 | 留言保存、分配范围、教师首次答复、学生读取自己的答复；无分配明确提示 | 不代表有人值守或承诺答复时限 |
| 预警审核 | `pass`、`reject`、`escalate`分别保存动作、原因、操作者和时间；兼容旧processed状态 | 不把旧processed记录补写成有依据的审核，也不自动触发校外联系 |
| 内部跟进 | 从留言/预警创建、指定期限、完成结果或取消原因；归创建教师且仍需当前分配 | 内部备注不是给学生的答复，也不代表线下干预已发生 |
| 个体导出 | 使用单一学生的授权端点；聚合导出入口另行保留 | 不扩大教师学生范围，不默认允许外部传播 |
| 教师账号运营 | 离线新教师开通、停用/启用与操作者审计；不提权既有学生 | 不代表接入校级身份系统、审批或人员核验已经完成 |
| AI评测 | 合成案例、独立人工评分输入、完整失败/超时分母和离线汇总工具 | 无真实模型效果、诊断准确率、临床效益或虚构成本 |
| 部署与恢复 | 最小镜像上下文、HTTP/TLS Compose、CI、SQLite一致性备份到新路径与恢复工具 | 静态配置不等于容器/Linux/TLS实际通过 |
| 申报与试点 | 按学校模板生成评审稿、预算变量模型、试点/隐私/责任清单 | 不虚构人员、资格、金额、校内批准或试点结果 |

## 数据保护与接口

原数据库、`.env`、上传目录均保留。增量schema只在隔离库或经备份的新私有运行副本应用，不在原库迁移；不自动创建真实账号、分配教师或调用真实模型。测试使用虚假账号、独立SQLite、合成业务文本和独立浏览器上下文，不操作用户已登录标签。

教师权限依赖独立`teacher_student_assignments`，自由填写的advisor不参与ACL。留言回复、预警处理和跟进的最终写入也验证分配条件，避免查询后撤权仍可写入。追加审核/跟进/操作事件由SQLite触发器阻止普通UPDATE/DELETE；这不是针对数据库管理员的防篡改存证。保留、删除、匿名化与审计保全的正式规则仍需校内责任人确认。

主要端点：

- 学生：`GET /api/student/questions`、`POST /api/student/questions/ask`。
- 教师留言：`GET /api/teacher/questions`、`POST /api/teacher/questions/{id}/answer`。
- 审核：`POST /api/teacher/crisis/review`、`GET /api/teacher/crisis/{id}/reviews`；兼容的advanced process仍须动作与原因。
- 跟进：`GET/POST /api/teacher/follow-ups`，`POST /api/teacher/follow-ups/{id}/complete`或`cancel`。
- 个体导出：`GET /api/advanced-teacher/students/{student_id}/export/docx`，不使用聚合dashboard导出代替。
