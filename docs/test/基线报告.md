## 后续复现

修复包索引连接并安装测试依赖后，从仓库根运行：

```powershell
.\.venv\Scripts\python.exe scripts/run-backend-baseline.py
```

隔离脚本在 `tmp/backend-baseline/` 为每次运行建立独立 SQLite，设置虚假测试密钥、禁用 dotenv 和 pytest 第三方自动插件，并通过 Python audit hook 阻止网络连接及 DNS。缺失的业务模块不会被伪造替身替代。现有测试若在 Windows 保留 SQLite 句柄，临时残留会留在被忽略目录，后续按明确路径处理。

当前只验证了“pytest 缺失时安全退出”分支；依赖补齐后的完整隔离运行仍待实际验证，不能把这个脚本的存在当作后端测试通过证据。

环境诊断另在 `C:\University\Files` 工作目录使用脚本绝对路径运行，仍正确定位项目，退出 0。检查时 8000 端口已有监听，5173/18080 无监听；脚本没有探测服务内容或终止进程，端口状态不能证明项目后端健康。Python Launcher 中一项 uv 管理的 3.11 候选未能取得版本输出，脚本如实显示 VERSION UNKNOWN，实际选用的根 `.venv` 3.12.14 检查通过。
