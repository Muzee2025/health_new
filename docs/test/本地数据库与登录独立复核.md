## 静态审查发现

`database.py` 从进程环境显式读取 `DATABASE_URL`，未配置时启动失败；创建 SQLAlchemy engine 本身不执行DDL，`get_db()` 才创建会话。当前模型定义包含 `teacher_student_assignments`，关系由教师/学生用户ID与唯一配对约束构成。`advisor` 是普通显示字段，不应成为权限来源。

`init-empty-database.py` 只接受不存在的新SQLite路径，使用排他创建，设置该路径作为进程内数据库配置后才导入模型并 `create_all()`；失败时保留新文件供检查。它不能用来初始化已经存在的备份副本。`metadata.create_all()` 可以创建缺失表，但不会为已有表补列或改变已有约束；因此不得把它当作通用升级器。

现有 `20261022-student-assignments.py` 是显式SQLite迁移：要求已存在的 `users` 表；`upgrade` 在事务中增加关联表、唯一约束与索引，若表已存在则先核对结构；`check` 只检查结构与关联行数；`downgrade` 在关联表非空时拒绝删除。该迁移不自动创建师生关联，也不校验操作员提供的关联双方角色。执行前仍须在隔离副本验证库格式、外键目标与目标路径。

历史工具 `backend/scripts/init_db.py` 明确调用 `drop_all()`，会删除目标库所有SQLAlchemy表，禁止用于运行库、备份或本轮演练。`backend/create_db.py` 是旧式建库脚本，包含内嵌凭证并尝试创建数据库；本轮不得运行，也不得把它作为部署路径。已有 `20260411_drop_risk_level.sql` 会删除列，适用方言和目标表需单独核实，不得因文件存在就对SQLite或当前副本执行。

`vite.config.js` 的 `/api` 和 `/static` 本地开发代理默认指向 `127.0.0.1:18080`，避免Lead已确认被其他Docker项目占用的8000。当前 `HEALTH_BACKEND_TARGET` 覆盖值限制为允许的loopback地址和端口范围；配置不符合条件时会拒绝，而不是代理至任意地址。此次未启动Vite或真实服务，代理行为仅作静态检查。

登录路由支持用户名、显示名和学号查找，使用bcrypt校验；缺失认证配置返回503，错误凭据返回通用401，注册只允许学生角色。我的测试使用虚假签名配置和合成数据；Lead的浏览器E2E验证了新注册合成学生的登录流程与错误密码401，没有使用真实账号或密钥。

新增 `run-local-backend.py` 要求显式env文件和本地端口范围，并在调用Uvicorn前清理父进程环境，只保留必要OS变量和显式env文件配置；要求数据库/JWT等关键项齐全，数据库必须是该部署目录下的绝对SQLite `health.db`，并拒绝URL参数、符号链接及启用RAG/模型下载。测试用stub拦截Uvicorn调用验证了环境与绑定参数，没有启动服务器。`prepare-local-database.py` 已移除 `--settings-from`，仅写入六个必要设置，不复制模型/API凭证。此前发现的父环境继承和配置复制风险已由Lead修正，并由本轮回归覆盖；启动脚本仍未在真实Windows进程环境执行。

Health readiness验证数据库可连、当前模型表和列名存在，并对异常返回脱敏503；它本身不核验列类型、可空性、默认值、索引、唯一约束或外键。Lead另提供的本地副本schema审计覆盖了这些结构类别，结果记录在下一节。

## 安全迁移建议

1. 将运行中的SQLite库视为不可写源。若服务正在使用WAL，应先停服进入维护窗口，或使用SQLite在线backup API从只读源生成新的目标副本；不得只复制活动中的主 `.db` 文件而遗漏WAL状态。先保存原件和只读备份的独立校验信息，所有 schema 试验只对新路径副本执行。隔离测试确认准备脚本使用 `mode=ro` 源连接与SQLite backup API，且合成源哈希未改变；尚未对真实源库或持久备份做演练。
2. 在副本上先作结构盘点：逐表比较当前SQLite的列、类型、可空性、默认值、主键、索引、唯一约束和外键与模型需要；只记录表名、列/约束名和聚合计数，不导出账号、内容或学生记录。识别缺表、缺列、旧列和方言差异后，编写有事务、幂等检查和失败回滚的显式迁移。不要用 `create_all()` 掩盖既有表结构漂移。
3. 对唯一缺失的师生分配表，先在副本执行 `check`，再经评审执行 `upgrade`，随后执行 `check` 并验证唯一约束、两条外键和索引。确认不产生任何自动关联。downgrade应验证空表可回滚、非空表被拒绝且行数不变。
4. 需要重新创建的环境只能通过操作者指定的新文件路径初始化；测试既有空文件和已有schema拒绝、导入失败保留新文件、初始化目标严格等于指定路径。原数据库与 `.env` 不覆盖、不改名、不删除；备份/新库路径不得指向符号链接或原件。
5. 数据库就绪后，独立设置项目端口与代理；启动前检查所选端口归属。当前启动器已限制loopback与18080、清理继承配置，Vite代理也限制目标地址。Lead已在本地新副本完成schema审计与readiness确认；后续启动仍应核实进程身份，且不得通过浏览器实际输入个人凭据验证。
