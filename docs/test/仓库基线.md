## 清理和数据保留

执行 `git ls-files -ci --exclude-standard` 后，仅对被新规则忽略的 111 个存量文件执行 `git rm --cached`。包括 Python 缓存、环境文件、数据库、上传文件、日志、coverage、诊断输出、编辑器和本地助手状态。清理前保存 SHA-256 清单，清理后逐个核对：111/111 仍在磁盘且字节一致。

- 根 `health.db`、`backend/health.db`、`backend/.env`、上传和其他运行目录保留本地，不迁移、不删除；哈希比对只检查字节是否保留，环境自检只报告变量设置状态，不展示内容。
- `.gitignore` 额外覆盖 `.venv/`、SQLite 辅助文件、向量库和临时输出；仅根前端 `.env.development` 和 `.env.example` 模板可跟踪。
- `tmp-dashboard-check.mjs` 原文移到 `scripts/archive/legacy-dashboard-fragment.mjs`；它是旧 Vue 片段，不是可执行验收工具。
- `dashboard/` 和 `picture/` 中共 4 个旧素材文件继续保留跟踪；等素材库及前端整合阶段确认引用和来源后处理。当前不把它们误报为运行垃圾。
- 六份旧文档保留正文后归档，映射见 [归档说明](../archive/README.md)。历史名称和历史指标不作为当前实现的依据。

`scripts/check-repo.py` 检查的是当前 Git 索引。新增文件和重命名登记到索引后运行，不能用尚未暂存的中间态作为最终门禁结果。它只查路径与文件大小，不扫描或输出文件内容。

## 主提示词口径更正

| 原描述或冲突 | W0 采用的解释 |
| --- | --- |
| 系统默认 Python 3.9，故必须另装 Python | 默认命令确为 3.9.13；`py -0p` 已发现 3.12/3.13/3.14 等候选。本轮另以可用的 bundled Python 3.12.14 创建根 `.venv` |
| 根目录运行数据必须清空，同时要求保留本地 | 保留数据优先。W0 只取消跟踪；数据库迁移留待数据层任务 |
| `env_file` 把 `.env` 带入镜像 | `env_file` 是运行期注入；实际构建风险来自 Dockerfile 的 `COPY backend /app` 且未发现 `.dockerignore` |
| 取消跟踪 `.env` 即代表密钥安全 | 历史提交仍含该文件；上线前需确认并轮换有效密钥。W0 不修改历史或外部账号 |
| 将 Python 变量 `SECRET_KEY` 误认成环境变量 | AST 复核确认 `routers/auth.py:13` 与 `utils/jwt_tokens.py:10` 的环境参数均是 `JWT_SECRET_KEY`。环境自检仍检查 `JWT_SECRET_KEY`，不新增错误变量要求 |
| 测试全绿才可通过 G0 | G0 要求如实记录已有测试基线；运行依赖阻塞必须记录，不伪装为通过，也不在 W0 改业务实现 |
| 当前名称唯一，所以历史旧名必须替换 | 当前入口统一心域智链，历史档案保留原文及来源 |
| G1 要求消除全部页面硬编码，而 W2 才改页面 | 后续 G1 先验素材/token/规范，页面迁移与全量色值清零属于 W2；正式执行前应在门禁中明确区分 |

## 已知后续风险

1. 认证、教师权限、注册角色、CORS、密钥默认值尚未加固；本轮未执行越权或上线安全验收。
2. `backend/app/database.py` 导入时读取配置并建立引擎，`main.py` 导入会建表，启动钩子会更新文章阅读量。禁止用现有库直接跑基线测试。
3. 后端依赖声明混合业务运行和大型 RAG/训练组件，当前测试环境未满足；详见基线报告。
4. 容器、TLS、备份恢复、前端响应式、素材许可、申报证据和预算均未完成最终验收。
5. 独立审计还发现 `backend/app/services/zhipu_emohaa_service.py` 的 `api_key` 存在硬编码默认值风险。这里只登记路径与变量名，不输出值；上线前必须移除默认凭据并确认轮换，W0 保持业务源码不变。
