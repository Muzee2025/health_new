## 目的与范围

使用仓库现有 SQLite 备份/恢复 CLI，对 runtime 目录中的历史快照做只读源 → 全新备份目标 → 全新恢复目标的闭环演练，确认工具能保留已有 schema 和外键违规并报告聚合检查结果。

本次只处理以下三份历史快照：

- `backend/runtime/local-20261022-153824/source-backup.db`
- `backend/runtime/support-20261022-145410/before-schema.db`
- `backend/runtime/support-20261022-145410/source-backup.db`

本次未打开或查询 `backend/health.db`、runtime 中的 `health.db`、`.env` 内容或服务日志。SQLite backup API 必须读取所选历史快照来复制数据库页；本次未执行行级 `SELECT`，未将行内容输出到终端或文档。未执行源库 SQL 写入、迁移、应用启动或旧 `backend/scripts/init_db.py`。运行及复核只记录退出码、`quick_check`、表数、外键违规总数和源文件是否保持不变，不记录行标识、账号标识、正文或风险值。

## 演练方法

- 使用仓库虚拟环境中的 Python 与 [`scripts/backup-restore-database.py`](../../scripts/backup-restore-database.py)。脚本以 `mode=ro` 打开输入；目标路径必须全新，已存在目标会被拒绝。
- 每份源快照分别执行 `backup` 到本轮随机新建目录，再从备份执行 `restore` 到另一个新目标。全部输出置于被 Git 忽略的 `tmp/data-governance/orphan-restore-drill-<随机目录>/`；未覆盖、复用或清理任何已有路径。
- 演练前后在本机比较三份源快照的 SHA-256 摘要，只记录比较结果，不写出摘要值；三份源文件均相同，前后未出现对应 WAL/SHM/journal 旁路文件。
- 本次使用的命令形式：

```powershell
.\.venv\Scripts\python.exe scripts/backup-restore-database.py backup `
  --source <历史快照路径> `
  --destination <全新隔离目录>/<快照代号>-backup.db

.\.venv\Scripts\python.exe scripts/backup-restore-database.py restore `
  --source <本轮备份目标> `
  --destination <全新隔离目录>/<快照代号>-restored.db
```

尖括号为本地路径占位符；实际目标使用本轮随机隔离目录。演练未运行测试套件，也未调用实际业务服务。

## 结论与限制

1. 3/3 历史快照均完成备份和恢复；共 6 次 CLI 调用，均 exit 0。
2. 每份目标均 `quick_check=ok`，恢复后的表数和外键违规总数与各自输入一致。演练证明该 CLI 能在全新目标路径复制这些历史 SQLite 文件，并保留现存外键违规。
3. 本次脚本没有运行完整 `integrity_check`、业务 API 或前端读取验证；也没有演练上传/文档卷、异机备份介质、加密/权限恢复、真实线上服务切换或 RPO/RTO。不能据此宣称真库恢复或生产灾备通过。
4. 外键违规仍存在于所有副本；本次未作删除、改绑或其他修复。数据归属与后续处置仍须业务责任人决定。
